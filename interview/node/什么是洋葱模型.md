Koa 洋葱模型描述的是多个中间件的组合和执行顺序。

请求进入时，中间件按照注册顺序执行 await next() 之前的代码；调用 next() 后把控制权交给下一个中间件。

当最内层中间件执行完成后，再按照相反顺序执行各个中间件 await next() 后面的代码，因此形成“先进后出”的洋葱结构。

然后马上画：

Request
   ↓
A before
   ↓
B before
   ↓
C before
   ↓
业务处理
   ↓
C after
   ↓
B after
   ↓
A after
   ↓
Response

代码：

app.use(async (ctx, next) => {
  console.log('A before')

  await next()

  console.log('A after')
})

app.use(async (ctx, next) => {
  console.log('B before')

  await next()

  console.log('B after')
})

app.use(async (ctx, next) => {
  console.log('C')
})

输出：

A before
B before
C
B after
A after

这一题你最好达到闭眼就能说出来。

三、为什么要设计成洋葱模型？

这和“什么是洋葱模型”是两个问题。

面试官：为什么 Koa 要使用洋葱模型？

你回答：

普通的单向中间件链只能很方便地处理请求进入阶段，但很多公共逻辑不仅需要在业务执行前做事情，还需要等待下游业务执行完成后继续处理。

比如统计请求耗时，需要请求进入时记录开始时间，等整个业务处理完成后再计算耗时；全局异常处理需要包裹整个下游执行过程；日志也可能既记录请求信息，又记录最终响应状态。

Koa 通过 async/await + next() 让中间件可以包裹下游执行过程，因此非常适合这些横切逻辑。



四、为什么一定要 await next()？
面试官追问：next() 我理解，为什么还要 await？

这题非常值得准备。

回答：

因为 next() 会执行下一个中间件，并返回一个 Promise。await next() 的意义是暂停当前中间件后半部分的执行，等待下游中间件全部执行完成以后，再继续执行当前中间件后面的代码。

正是这个等待过程形成了洋葱模型的“出去以后再回来”。

例如：

console.log(1)

await next()

console.log(2)

不是：

1
2
下一个中间件

而是：

1
↓
下一个中间件
↓
下下个中间件
↓
全部完成
↓
2

这实际上就是你已经学过的 async/await：

async function A() {
  console.log('A before')

  await B()

  console.log('A after')
}

Koa 的：

await next()

本质上可以先理解成：

await 后面的中间件()
五、不写 await next() 会怎么样？

20k 面试很可能从这里继续。

假设：

app.use(async (ctx, next) => {
  console.log(1)

  next()

  console.log(2)
})

app.use(async ctx => {
  await doSomething()
  console.log(3)
})

因为没有：

await next()

当前 middleware 不会等待下游执行完成。

可能出现：

1
↓
启动下游
↓
2
↓
下游异步完成
↓
3

那么你原本想：

const start = Date.now()

await next()

console.log(Date.now() - start)

统计整个请求耗时。

结果不 await：

const start = Date.now()

next()

console.log(Date.now() - start)

很可能下游还没处理完，你就统计结束了。

所以一句话：

不 await next，就无法保证当前中间件的后置逻辑在下游全部执行完成之后运行，也会破坏洋葱模型的预期执行顺序。

六、为什么洋葱模型特别适合错误处理？
面试官：Koa 怎么做统一异常处理？

这道非常高频。

app.use(async (ctx, next) => {
  try {

    await next()

  } catch (err) {

    ctx.status = 500
    ctx.body = {
      message: err.message
    }
  }
})

里面：

app.use(async ctx => {
  throw new Error('数据库异常')
})

执行：

try
 ↓
await next()
 ↓
middleware B
 ↓
Controller
 ↓
Service
 ↓
throw Error 💥
 ↑
Promise reject
 ↑
await next() 抛异常
 ↑
catch
 ↓
统一处理

面试回答：

因为外层 middleware 的 await next() 等待的是整个下游 Promise 链，如果下游发生未捕获异常导致 Promise reject，异常可以沿调用链向上传递，由最外层的 try/catch 统一捕获，因此很适合实现全局错误处理。

这个回答已经比较漂亮了。

七、洋葱模型和 async/await 到底什么关系？

这是你刚才最困惑的地方。

面试官：洋葱模型是不是为了解决异步？

回答：

不能简单理解成解决异步。

Koa 的业务本身大量涉及数据库、网络、文件等异步操作，而 async/await 可以让异步流程更容易组织。

Koa 在这个基础上通过 await next() 组合多个异步中间件，使每个中间件既能在下游执行前处理逻辑，又能等待下游完成后执行后置逻辑，从而形成洋葱模型。

所以 async/await 是实现洋葱模型的重要机制，而洋葱模型主要解决的是中间件组合和控制权传递问题。

你可以记：

Promise
   ↓
async / await
   ↓
await next()
   ↓
等待下游 middleware
   ↓
下游完成
   ↓
恢复上游
   ↓
洋葱模型

这条链非常重要。

八、next() 到底是什么？
面试官：next 是什么？Koa 给你的一个特殊关键字吗？

不是。

回答：

next 本质上是一个函数，调用它会执行后面的中间件，并返回 Promise。Koa 内部会把注册的 middleware 组合起来，使当前 middleware 能通过 next 调用下一个 middleware。

概念上可以先想象：

middleware1(ctx, () => {
  return middleware2(ctx, () => {
    return middleware3(ctx)
  })
})

真实实现当然不会这么简单，但这个模型能帮助你理解。

最终形成类似：

middleware1(
    middleware2(
        middleware3()
    )
)

这也是为什么叫“洋葱”：

┌─────────────────────────┐
│ middleware A            │
│   ┌─────────────────┐   │
│   │ middleware B    │   │
│   │   ┌─────────┐   │   │
│   │   │    C    │   │   │
│   │   └─────────┘   │   │
│   └─────────────────┘   │
└─────────────────────────┘
九、ctx 又是什么？
面试官：为什么 Koa 不直接给你 req 和 res，而是 ctx？

回答：

ctx 是 Koa 对一次 HTTP 请求和响应相关信息的封装，也就是 Context。它把 Node 原生的 request、response 以及 Koa 提供的便捷 API 组织到一个上下文对象中。

所以中间件可以通过 ctx 获取请求信息，也可以设置响应。

例如：

app.use(async ctx => {

  // Request
  console.log(ctx.method)
  console.log(ctx.url)
  console.log(ctx.headers)

  // Response
  ctx.status = 200
  ctx.body = {
    success: true
  }
})

你可以暂时理解：

ctx
│
├── request相关信息
│
├── response相关信息
│
└── 当前请求的一些状态
十、中间件可以阻止后面的 middleware 吗？

当然可以。

面试官：鉴权失败以后怎么阻止后续业务？

不调用：

next()

就行。

例如：

app.use(async (ctx, next) => {

  if (!ctx.headers.authorization) {
    ctx.status = 401
    ctx.body = 'Unauthorized'

    return
  }

  await next()
})

流程：

Request
   ↓
Auth Middleware
   ↓
Token？
 │
 ├─ 没有 → 401 → Response
 │
 └─ 有
     ↓
 await next()
     ↓
 Controller

所以 next() 其实还有一个非常重要的意义：

控制请求是否继续向下传播。

十一、中间件顺序重要吗？

非常重要。

例如：

app.use(errorMiddleware)
app.use(loggerMiddleware)
app.use(authMiddleware)
app.use(router)

大致：

Error
  ↓
Logger
  ↓
Auth
  ↓
Router

如果你希望：

Error Middleware 捕获后面所有中间件的异常

那它必须包在比较外层。

因为：

try {
  await next()
} catch {}

只有 next() 后面的链路才能被它包住。

所以面试可以回答：

Koa middleware 的注册顺序会影响洋葱模型的嵌套关系，因此顺序非常重要。比如全局异常处理中间件通常应该放在比较外层，这样才能捕获后续 middleware 和业务代码抛出的异常。

十二、Express 和 Koa 中间件有什么区别？

这题你既然看到了：

team behind Express

就很容易被问。

20k 前端不用把 Express 源码背下来。

回答到这里：

Express 和 Koa 都使用 middleware 思想，但 Koa 的一个核心特点是基于 Promise 和 async/await 的 middleware 组合，通过 await next() 可以非常自然地实现前置和后置处理，也就是通常所说的洋葱模型。

Koa 本身也比较轻量，把很多能力交给独立中间件生态实现。

如果继续追历史：

Koa 早期版本使用 Generator/yield，Koa 2 转向 async/await。

十三、数据库查询是不是 middleware？

这题是我专门针对你刚才的理解给你加的。

面试官：

数据库查询属于 middleware 吗？

你不要回答“是”。

应该：

不一定。middleware 是一种请求处理机制，但实际项目通常会分层。

日志、鉴权、异常处理等横切逻辑适合 middleware；具体的订单查询、商品计算、数据库操作一般放在 Controller/Service/Repository 等业务层中。

middleware 可以触发这些业务，但不代表所有请求处理代码都应该写成 middleware。

结构：

Middleware
   ↓
Router
   ↓
Controller
   ↓
Service
   ↓
DAO / Repository
   ↓
Database

这个非常重要，因为否则面试官容易觉得你没有真实 Node 后端分层概念。

Q：什么是中间件？

A：HTTP 请求处理链中可组合、可复用的处理函数，常用于日志、鉴权、异常处理等横切逻辑。

Q：Koa 中间件长什么样？

A：async (ctx, next) => {}，ctx 是请求上下文，next 用于调用下一个 middleware。

Q：什么是洋葱模型？

A：请求按照注册顺序向内执行 next 前的逻辑，下游执行完成以后再反向执行 next 后的逻辑。

Q：为什么要这么设计？

A：让 middleware 可以包裹下游处理过程，既做前置处理，又做后置处理，适合日志、异常处理、耗时统计等横切逻辑。

Q：为什么是 await next()？

A：next 返回 Promise，await 用于等待下游 middleware 全部完成，再继续当前 middleware 的后置代码。

Q：不 await 呢？

A：当前 middleware 不等待下游完成，后置逻辑可能提前执行，破坏预期的洋葱顺序。

Q：怎么统一处理异常？

A：最外层 middleware 用 try { await next() } catch {}，下游 Promise reject 可以向上传递。

Q：鉴权失败怎么终止？

A：不调用 next，直接设置 ctx.status/body 返回。

Q：中间件顺序重要吗？

A：重要，它决定洋葱嵌套关系，比如错误处理通常放外层。

Q：数据库查询也是 middleware 吗？

A：一般不是横切 middleware，而属于 Service/Repository 等业务层。

Q：和 Express 有什么区别？

A：两者都有 middleware 思想，Koa 更强调 Promise + async/await 的组合模型，通过 await next 很自然地实现前后置逻辑。
