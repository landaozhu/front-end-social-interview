# Webpack 减少包体积

## 1. 删除无用代码

### Tree Shaking

Webpack Tree Shaking 基于 ES Module 的静态 import/export，只标记未使用的导出（unused export）。压缩插件（如 Terser）会删除这些未使用的导出，从而减小 bundle 体积。

### 按需 polyfill

- `@babel/preset-env` + `useBuiltIns: 'usage'` + `corejs: 3`。
- 只引入源码实际用到的 polyfill → 减少冗余代码。

---

## 2. 拆分与复用模块

### splitChunks / cacheGroups

- 把第三方库（React、Lodash、`core-js` 等）提取到 **vendor** chunk。
- 多入口共享模块只生成一份 → 减少重复代码。

### runtimeChunk: `'single'`

- 单独提取 **runtime** → 入口业务改动不易牵动 vendor。
- vendor 的 **hash** 更稳定 → 浏览器缓存利用率更高。

### DLL / DllPlugin（可选）

- 对大型、更新少的依赖 → 预编译，主 bundle 引用不变。
- 在 Webpack 5 配合 **runtime** + **splitChunks** 时多为可选项，按项目评估。

---

## 3. 压缩优化

### TerserPlugin

- 移除 `debugger`、可按配置移除 `console`、死代码等。
- `collapse_vars` / `reduce_vars` 等 → 合并重复静态表达式，进一步缩小体积。

### CssMinimizerPlugin + MiniCssExtractPlugin

- CSS 抽出为独立文件，JS bundle 不背负样式字符串。
- 压缩 CSS → 减少传输与解析成本。

---

## 4. 精简依赖

### 按需引入库

- 例如 `import debounce from 'lodash/debounce'` 或 `import { debounce } from 'lodash-es'`，避免整包 `lodash`。
- 优先选支持 **ESM / tree-shaking** 的包版本。

### 避免多余 polyfill 与插件

- 删除未使用的 loader / plugin。
- loader 顺序与范围（`include` / `exclude`）合理 → 减少重复转换与打进 bundle 的无关代码。

---

## 5. Scope Hoisting / Module Concatenation

- `optimization.concatenateModules: true`（**生产模式默认启用**）。
- 多个模块合并到同一作用域 → 减少 IIFE 等包装 → bundle 更小、运行时略省开销。
