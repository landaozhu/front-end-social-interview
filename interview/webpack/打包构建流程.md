# Webpack 打包构建流程

## 面试话术

1. 先介绍 **Webpack 5** 背景：为什么需要它、解决什么问题。
2. 大致思路、整体流程：以下文 **「具体过程」** 中的阶段为模板展开。
3. 结合项目：在某某场景里通过 **自定义 loader / plugin** 解决了什么问题。
4. 设计思想（可点到为止）：
   - 基于 **Tapable** 的钩子机制；
   - **AOP**（面向切面）：在核心流程外挂载扩展，与 **OOP**、**FP**（如 React Hooks、Vue Composition API 中的组合思想）可对比着谈。

---

## 背景

1. 前端资源种类多：`img`、`font`、`css`、`js`、`ts`、`vue` 等，最终要输出可部署产物。
2. 很多资源需要 **加工**：
   - `ts` → `ts-loader`（或 `babel-loader` + TS）；
   - `js` → `babel-loader`；
   - `css` → `css-loader` + `mini-css-extract-plugin` / `style-loader`；
   - `html` → `html-webpack-plugin`。
3. 对产物做 **优化**：`optimization`、`splitChunks` 等；若所有资源打成一个文件，不利于缓存与加载，因此有 **分 chunk**、**CSS 提取** 等能力。
4. **输出产物** 到磁盘（或 dev 时到内存 / 中间结果）。

## 具体过程

### 1. 初始化（Initialize）

- 读取 `webpack.config.js`，并与 Shell / CLI 参数合并。
- 创建 **Compiler** 实例，内部持有 `entry`、`output`、`mode`、`module.rules`、`plugins` 等配置。

示意（概念代码，非完整源码）：

```js
class Compiler extends Tapable {
  constructor(context) {
    super();
    this.hooks = {
      beforeCompile: new AsyncSeriesHook(['params']),
      compile: new SyncHook(['params']),
      afterCompile: new AsyncSeriesHook(['compilation']),
      make: new AsyncParallelHook(['compilation']),
      entryOption: new SyncBailHook(['context', 'entry']),
      // … 更多钩子
    };
    // …
  }
}

function webpack(options) {
  const compiler = new Compiler(/* … */);
  // 若 options.watch 为 true，则进入 watch 流程
  return compiler;
}
```

- **Compiler** 继承自 Tapable，初始化时注册大量生命周期钩子。
- **注册插件**：插件订阅 Compiler（及后续 Compilation）上的钩子，在对应阶段执行逻辑。

---

### 2. 确定入口（Entry）

根据 `entry` 找到打包起点。

**单入口**：

- `entry: './src/index.js'`
- `entry: () => './demo'`

**多入口**：

- `entry: ['./home.js', './about.js']`
- `entry: { home: './home.js', about: './about.js' }`
- `entry: () => new Promise((resolve) => resolve(['./demo', './demo2']))`

**异步解析入口示例**（官方文档风格）：

```js
entry() {
  return fetchPathsFromSomeExternalSource();
  // resolve 成类似 ['src/main-layout.js', 'src/admin-layout.js'] 的路径列表
},
```

- 每个入口对应生成 **Chunk**（一组相关模块的集合）；此阶段插件也可改写 `entry`。

---

### 3. 构建模块（Build Modules）

- **递归解析依赖**：从入口开始，处理 `import` / `require` / 动态 `import`。
- 形成 **Module**：每个模块可对应 AST 等中间表示；配合 Tree Shaking 等可分析 **export 是否被使用**（未使用可视为 dead code 候选）。
- **Loader 链路**：按 `test` / `include` / `exclude` 匹配规则，对资源做转换：
  - JS：Babel；
  - CSS：`css-loader` → `style-loader` 或提取插件；
  - 静态资源：`file-loader` / `url-loader`（旧）或 **Asset Modules**（Webpack 5）。
- 得到带 **依赖信息** 的 Module 对象（内容已按 loader 输出）。

---

### 4. 构建依赖图（Dependency Graph）

- Webpack 根据模块依赖建立 **有向图**：节点为 Module，边为依赖关系。
- 分析 **哪些模块属于同一 chunk**、**动态 import 对应异步 chunk**。
- **chunkhash / contenthash**：按 chunk 或内容生成 hash，服务缓存与文件名策略。

---

### 5. 优化阶段（Optimization）

- **Tree Shaking**：如 `optimization.usedExports` 等与副作用分析配合，标记未使用导出。
- **压缩**：`optimization.minimize` + `TerserPlugin` 等（去除 dead code、压缩）。
- **SplitChunks**：`optimization.splitChunks`，抽公共依赖为独立 chunk，利于缓存与并行加载。
- **Runtime 提取**：如 `optimization.runtimeChunk: 'single'`，避免多 entry 重复打包 runtime。
- **稳定 ID**：如 `moduleIds: 'deterministic'`，有助于长期缓存下 hash 稳定。

---

### 6. Chunk 封装（Chunking / Bundling）

- 按 entry、动态 import、`splitChunks` 等规则将 Module 归入 **Chunk**；封装前可进一步 **移除未使用 export**（与优化阶段衔接）。
- 每个 Chunk 可对应输出 JS / CSS / 资源；内部包含 **webpack runtime**、模块加载与 **CJS / ESM** 互操作等包装逻辑。

---

### 7. 输出资源（Emit / Output）

- 生成最终 **Assets**：如 `[name].[chunkhash:8].js`、`[contenthash:8].[ext]`。
- **插件介入**：如 `HtmlWebpackPlugin` 在 emit 前后注入 HTML、引用打包后的资源。
- 写入 **磁盘** 或 **内存**（如 `webpack-dev-server`）。

---

### 8. 生命周期小结

**Compiler 侧常见钩子**（名称因版本与文档略有差异，面试记主干即可）：

- `run` / `beforeRun`
- `compile` / `afterCompile`
- `emit` / `afterEmit`
- `done`

**Plugin** 可在上述阶段读写 **Module、Chunk、Assets**，实现自定义行为。

---

## 完整流程示意

```text
webpack.config.js
        │
        ▼
   Compiler 初始化
        │
        ▼
   Entry 确定 → 生成 Chunk
        │
        ▼
   构建 Module → Loader 转换
        │
        ▼
   生成依赖图 → 计算 ChunkHash / ContentHash
        │
        ▼
   优化阶段：
     ├─ Tree Shaking → 移除未使用代码
     ├─ SplitChunks → 提取公共模块
     ├─ Runtime 提取
     └─ 压缩 JS/CSS
        │
        ▼
   封装 Chunk → runtime + module 包装
        │
        ▼
   输出 Assets → 写入 dist
        │
        ▼
   浏览器加载 → hash + 缓存控制
```
