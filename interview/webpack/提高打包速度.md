# Webpack 提高打包速度

## 1. 构建流程优化

### 减少编译文件量

- 使用 `exclude` / `include` 精准匹配 loader，避免整个 `node_modules` 走 `babel-loader`。

```js
{
  test: /\.js$/,
  exclude: /node_modules/,
  use: 'babel-loader',
}
```



### 按需打包

- 多入口项目只打包变更的 entry。
- 动态 `import` / **Code Splitting** → 减少初始打包体积。

### 避免不必要的 loader / plugin

- 开发模式避免使用 `MiniCssExtractPlugin`（可用 `style-loader`）；压缩类插件生产模式再启用。

---

## 2. Loader / Plugin 优化

### 缓存

- `babel-loader` / `ts-loader` 启用 `cacheDirectory`。
- CSS 相关 loader 在合适场景下可开启缓存。


### 多线程 / 并行

- `babel-loader` + **`thread-loader`**（在 worker 池中跑 loader）。
- **`TerserPlugin`** 并行压缩：（Webpack 4 生产模式 (mode: 'production') 默认启用了 UglifyJsPlugin（Webpack 4.0–4.36）
从 Webpack 4.37+ 开始，生产模式默认改用 TerserPlugin 压缩 JS）
```js
new TerserPlugin({ parallel: true })
```

### 减少插件执行开销

- 开发模式只启用必要插件。
- 多入口项目可针对 entry 配置 `HtmlWebpackPlugin`，避免重复生成。

---

## 3. 缓存策略

### 模块缓存（开发环境）

- Webpack 5 **filesystem cache** → 复用上次编译结果。
- **HMR** → 只动少量模块，不全量重建。

### 依赖缓存

- Babel / PostCSS / Loader 缓存 → 开发模式常能明显提速。
- Webpack 4 可用 `cache-loader`；Webpack 5 优先用内置 cache。
### 浏览器缓存（生产环境）

- 使用 [contenthash] / [chunkhash] → 文件内容不变时浏览器直接使用缓存
- 配合 splitChunks + runtimeChunk: 'single' → 确保共享模块（vendor）和 runtime hash 稳定
---

## 4. 并行与增量构建

### 多线程

- **`thread-loader`** → 与 `babel-loader` / `ts-loader` 等配合，多核并行。
- **`TerserPlugin.parallel`** → 并行压缩 JS。

### 增量构建

- **HMR** → 只替换变更模块。
- **watch** / 增量重建 → 复用上次构建结果。

---

## 5. 高级策略

### DllPlugin / DllReferencePlugin（webpack5有配置runtime就不需要了）

- 对大型依赖（React、Vue、lodash 等）单独打包；后续构建引用预编译 dll，减轻全量构建压力。



### Scope Hoisting / Module Concatenation（Webpack 5 默认生产模式启用）

- 生产模式可依赖 `optimization.concatenateModules`（生产默认行为）减少模块包装开销，兼顾体积与部分构建/解析成本。

### Babel / TypeScript

- Babel 插件精简，按需 polyfill。
- TypeScript：`ts-loader` 的 `transpileOnly: true`（或 `babel-loader` + `@babel/preset-typescript`）→ 避免在打包链路里做全量类型检查（类型检查交给 IDE / `tsc --noEmit`）。
