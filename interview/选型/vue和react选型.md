# Vue 和 React 怎么选型？

25k 一面过关线：能说出 **按团队、存量、页面形态选，不站队**；能用猫眼 Vue、携程 React 各举一例；追问能讲 **更新模型差在哪、为什么上单不改 React**。只背区别表或贬其中一边，过不了。

技术差异见 [vue和react区别](../对比题/vue和react区别.md)。本题只讲 **怎么选**。

---

## 开口（40 秒）

两边都用过。选座 / 上单用 Vue，Trip.com 地图用 React，都是团队存量，不是我从零颁标准。

新项目看四件事：人会什么、已有组件库和基建、页面是表单配置还是强交互 / SSR、值不值得为 Concurrent 那套买单。中后台、Vue 人多 → Vue；复杂交互、已有 React SSR → React。核心链路不会为了「试试」推翻重写。

---

## 怎么落到项目上

| 项目 | 为什么是这个栈 |
|------|----------------|
| 猫眼选座 / 上单 | Vue 团队 + 表单 / 状态机多 + 要和小程序分端，写得快 |
| Trip.com 地图 | 国际站 React SSR + Redux，地图生态也在这套上 |
| 上单 2.0 | 存量 Vue2，迁 Vue3 + qiankun；换 React 等于重写，收益盖不住 |

一面别说「React 更高级」。说得清 **换栈的迁移成本和招聘**，比喊性能更像做过。

---

## 追问

- **和区别那题？** 区别是响应式 vs setState、模板 vs JSX。选型是团队和业务。
- **Vue3 有 composition，是不是没差了？** 复用像，更新模型不像：Vue 谁用了谁更新；React 默认子树跟着 render，靠 memo / Concurrent 控。
- **新 C 端你选哪个？** 先问人和要不要 SSR / 小程序，再给结论，不要秒答一个名字。
