【一句话总结】
Hash 模式利用 URL 中的#符号，通过监听hashchange事件实现路由，兼容性好且无需服务器配置；History 模式使用 HTML5 History API 操作无#的真实路径，URL 更美观但对服务器有要求。
核心差异与选型
特性	Hash 模式	History 模式
URL 表现	example.com/#/home	example.com/home
实现原理	监听window.onhashchange事件	调用history.pushState()并监听popstate事件
服务器要求	无特殊要求	必需配置（将所有路由 Fallback 到index.html，否则刷新 404）
兼容性	IE8+	IE10+
美观度	较差（有#）	优美（无#，更像真实URL）
选型建议：

追求简单部署和极致兼容性 → 选 Hash
追求美观和现代应用体验 → 选 History（并记得配置服务器）


追问：History 模式下，在 /user/1 按 F5 刷新为什么常 404，Hash 的 /#/user/1 却不会？服务器要怎么配？

F5 会把完整 URL 发给服务器。Hash 里 # 后面浏览器不带给服务器，服务器只收到 /，能回到 index.html。History 的 /user/1 服务器当真实路径找文件，没有就 404。所以要用 nginx 等把所有前端路由 fallback 到 index.html，再交给前端路由。
追问：
追问：history 刷新怎么接，created 还是 mounted？

先分清两件事：**404 是服务器的事，不是生命周期能接住的。** nginx 没 fallback，F5 根本到不了 Vue，谈 created / mounted 没有意义。

服务器已经把 `index.html` 吐回来之后，刷新就是 SPA **冷启动**：JS 执行 → 装 Router → 读 `location.pathname`（如 `/user/1`）匹配路由 → 再创建页面对应组件。`$route` 在该组件 **created 之前就已经在**，不需要等到 mounted 才「接上」。

| 你要干什么 | 放哪 |
|------------|------|
| 用 `this.$route.params` 拉详情 | **created**（Vue3 在 `setup` / `onBeforeMount` 也行） |
| 量 DOM、绑原生事件 | **mounted** |
| 客户端点链接换路由 | 组件可能被复用，要 **watch `$route`**；刷新是整页重来，组件是新建的，不靠这次 watch 第一次 |

面试原话：History 刷新接路由靠的是 **服务端 fallback + 启动时 Router 读 pathname**，不是在 mounted 里补一刀。参数请求放 created 即可。
