# decimal / 浮点数精度原理（为什么 0.1+0.2 !== 0.3）

【一句话】JS 的 `Number` 是 **IEEE 754 双精度**，十进制小数多数无法用二进制有限表示，只能近似，加减就有误差。金额不要用 Number 直接算。

```js
0.1 + 0.2 === 0.3  // false，实际 0.30000000000000004
```

## 原理

- 1 位符号 + 11 位指数 + 52 位尾数  
- 0.1 的二进制是无限循环，截断后存的是近似值  
- 两个近似值相加，再转回十进制，就对不上 0.3  

整数在 `Number.MAX_SAFE_INTEGER`（2^53-1）内是精确的；小数不保证。

## 怎么处理

| 场景 | 做法 |
|---|---|
| 展示 | `toFixed(2)` 只负责显示，**不能当精确计算** |
| 金额 | 用分作整数：`199` 分而不是 `1.99` 元 |
| 真正十进制 | `decimal.js` / `bignumber.js`，按十进制位运算 |
| 比较 | 看误差 `Math.abs(a - b) < Number.EPSILON`（仅限近似比较） |

面试说 decimal 原理：它按十进制字符串/位来存，加减乘除走十进制规则，避开二进制浮点。代价是慢、包体积。

## 追问

- **BigInt？** 只解决大整数，不解决小数。
- **JSON？** JSON 没有 decimal 类型，金额建议字符串或整数分传输。
