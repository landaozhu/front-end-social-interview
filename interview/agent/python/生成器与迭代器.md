迭代器是实现了 `__iter__` + `__next__` 的对象，每次 `next()` 吐一个值，抛 `StopIteration` 结束。生成器是用 `yield` 写出来的迭代器，调用函数不执行到结束，而是返回一个生成器对象。

Agent / LangChain 里这题常接到 **流式输出**：模型不是一次吐完整答案，而是 token 接着 token 过来。

## 核心差别

| | 列表 | 生成器 |
|--|------|--------|
| 内存 | 一次性全在内存 | 用一个算一个 |
| 能不能多次遍历 | 能 | 一般一次性，走完就空 |
| 写法 | `[x for x in xs]` | `(x for x in xs)` 或 `yield` |

```python
def chunks(text, n=20):
    for i in range(0, len(text), n):
        yield text[i:i + n]

for part in chunks('hello langchain'):
    print(part)
```

`yield` 会暂停函数，下次 `next()` 从暂停处继续，局部变量还在。这就是「惰性」。

## 和 LLM streaming 的关系

`model.stream(prompt)` 返回的是迭代器：每步一个 chunk。你在 for 里拼起来给前端，而不是等 `invoke` 全部完成。

```python
for chunk in model.stream('用一句话说什么是 Agent'):
    print(chunk.content, end='', flush=True)
```

异步对应 `async for chunk in model.astream(...)`。本质都是「生产者慢慢吐，消费者慢慢用」，避免把整段回复堵在一次 RPC 里。

## 面试 60 秒

迭代器按需取值；生成器是 `yield` 版迭代器，省内存、适合流。LangChain 的 `stream` / `astream` 就是这个模型：token 流而不是整包 JSON。列表能反复遍历，生成器默认一次性。

## 追问

**生成器和协程？**

生成器是同步惰性序列。`async def` + `await` 才是协程。LLM 流式用生成器或异步生成器都可以，看调用链是 sync 还是 async。

**`yield from` 干什么？**

把子生成器的值原样转发出去，相当于 for 里再 yield，写 RAG 分段拼接时能用到。

**为什么大文件 / 超长文档不用 list 一次读完？**

内存和首 token 时间。生成器 / 流式切分才能边读边 embedding。
