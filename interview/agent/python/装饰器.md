装饰器就是「用一个函数包住另一个函数」，在不改原函数源码的前提下，加日志、缓存、校验、注册。语法糖 `@deco` 等价于 `fn = deco(fn)`。

LangChain 的 `@tool` 就是装饰器：把一个普通 Python 函数登记成工具，自动带上名字、文档字符串、参数 schema，给 Agent / `bind_tools` 用。

## 怎么写

```python
def log_call(fn):
    def wrapper(*args, **kwargs):
        print('call', fn.__name__)
        return fn(*args, **kwargs)
    return wrapper

@log_call
def add(a, b):
    return a + b
```

带参数的装饰器是「三层」：最外层收装饰器参数，中间层收函数，内层才是真正调用。

```python
def retry(times):
    def deco(fn):
        def wrapper(*args, **kwargs):
            last = None
            for _ in range(times):
                try:
                    return fn(*args, **kwargs)
                except Exception as e:
                    last = e
            raise last
        return wrapper
    return deco
```

要用原函数名字和签名时，内层加 `functools.wraps(fn)`，否则 `__name__` 会变成 `wrapper`，LangChain 靠 docstring / 签名生成 tool schema 时会乱。

## 和 @tool 的关系

```python
from langchain_core.tools import tool

@tool
def search_weather(city: str) -> str:
    """查城市天气。"""
    return f'{city}: 晴'
```

`@tool` 会：

1. 用函数名当地 tool name
2. 用 docstring 当描述（给 LLM 看要不要调）
3. 用类型注解生成参数 JSON Schema

所以 **写 tool 时 docstring 和类型注解不是装饰，是协议**。

## 面试 60 秒

装饰器是高阶函数，`@f` 就是 `fn = f(fn)`。LangChain `@tool` 用它把函数注册成带 schema 的工具。自己写装饰器记得 `*args, **kwargs` 和 `wraps`，否则 tool 的名字和签名会丢。

## 追问

**装饰器和闭包？**

装饰器几乎一定闭包：`wrapper` 要抓住外层的 `fn` 或 `times`。

**和 Java 注解 / TS 装饰器比？**

Python 装饰器是运行时的函数替换；Java 注解偏元数据，要靠反射或编译处理。TS 装饰器也是实验特性，和 Python 不是同一套。

**为什么 tool 必须有类型注解？**

LLM 只能看 schema。没有注解，LangChain 只能猜成通用 string，调用容易传错。
