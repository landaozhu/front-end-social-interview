Agent 是 **能使用工具、自己决定下一步** 的 LLM 程序。它不是「更会聊天的 Chatbot」，也不是「写死步骤的脚本」。

| | Chatbot | Chain / Workflow | Agent |
|--|---------|------------------|--------|
| 能力 | 对话 | 固定流水线 | 推理 + 选工具 + 循环 |
| 下一步谁定 | 用户 | 开发者 | **模型** |
| 外部世界 | 一般没有 | 预定的检索/API | 按需调 tool |

用户说「帮我看看明天去上海要不要带伞，再订一张下午的票」：Chatbot 只能空谈；Chain 必须你预先写「先天气后订票」；Agent 可以先调天气 tool，再决定要不要调订票 tool。

## 最小闭环

```text
目标 → 模型思考 → 选一个 Action（tool 或结束）
      ↑                    ↓
      └── Observation ← 执行 tool
```

停下来的条件：模型声明最终答案，或达到最大步数。每一步都在花 token，所以 Agent 更贵、更慢、更难测。

## 什么时候不要用

- 步骤固定（表单抽取、翻译、已有检索问答）→ Chain
- 强事务、强合规（支付、删库）→ 人工确认或规则引擎，不要让模型直接拍板
- 一次 function call 就能干完 → `bind_tools` 单轮即可，不必上循环 Agent

## 面试 60 秒

Agent = LLM + Tools + 循环：模型决定调不调工具、调哪个，直到给出答案。Chatbot 无工具，Chain 路径写死。能预知步骤就不要上 Agent，贵且不稳。

## 追问

**和 Copilot / ChatGPT 插件的关系？**

都是 tool calling 产品形态。面试答清「模型选工具、宿主执行」即可。

**多 Agent？**

多个角色分工（规划 / 执行 / 审查）。编排会走到图，**先不展开**；先把单 Agent 循环讲清楚。
