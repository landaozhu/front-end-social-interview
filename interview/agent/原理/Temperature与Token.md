这题考的是 **你能不能控制一次调用的随机性、长度和钱**。

## Temperature

采样温度。越低越确定、越重复；越高越多样、越容易跑飞。

- 抽取、分类、tool 参数、代码 → **低**（0～0.2）
- 写文案、头脑风暴 → 可以高一点（0.7 左右）
- RAG 问答偏事实 → 偏低，减少幻觉

温度不是「智商旋钮」。0 也会错，只是错得更稳定。

## Token

模型读写的单位，大约亚词，不是字符也不是汉字一一对应。中文一个字常常 1～2 个 token。

计费和上下文都按 token：

- **输入 token**：system + 历史 + 检索块 + 本轮问题
- **输出 token**：模型新生成的

上下文窗口是输入+输出的上限（有的厂商分开算）。超了会截断或报错。所以 Memory 要裁剪，RAG 的 Top-K × 块大小要算过。

`max_tokens` 限制的是 **输出** 长度，不是窗口总量。

## 面试 60 秒

Temperature 管随机性，事实任务调低。Token 是计费和窗口单位，中文往往更贵。窗口要同时算历史和检索。Agent 多一轮就多付一轮输入（含之前的 tool 结果），所以循环次数就是钱。

## 追问

**top_p 和 temperature 一起调吗？**

两者都影响采样，生产一般固定一个、微调另一个，避免不可复现。面试说「不要两个一起猛拧」即可。

**streaming 和 token？**

流式是按生成到的 token 往下推，计费仍按最终输入输出总量，不会因为流式更便宜。
