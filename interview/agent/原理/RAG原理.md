RAG（Retrieval-Augmented Generation）= **先检索再生成**。模型参数里没有的知识（公司文档、最新新闻），不靠它背，而是每次问答现场查出相关片段，塞进 Prompt，再让模型基于片段说话。

```text
问题 → 检索（向量 / 关键词）→ Top-K 片段 → 和问题一起进 LLM → 答案
```

## 为什么需要

| 手段 | 解决什么 | 代价 |
|------|----------|------|
| 更大模型 | 更会说 | 仍会过时、仍不知道你的私有库 |
| 微调 | 风格、格式、领域口径 | 贵、更新知识慢 |
| **RAG** | **知识常变、要可引用** | 检索质量和切块 |

三者不互斥：RAG 管知识新鲜和可追溯；微调管语气和任务格式。

## 检索在干什么

文档切块 → embedding → 向量库。问题也 embedding，取相似块。也可以上 BM25 关键词。混合往往比纯向量稳（专有名词、工单号）。

生成侧 Prompt 要约束：「只根据资料回答，没有就说没有」，并让模型带上引用。否则它会忽略资料自己编。

## 面试 60 秒

RAG 用检索补模型知识：切块、向量化、Top-K、拼进 Prompt 再生成。适合私有文档和常更新内容。效果首先取决于切块和检索，不是换大模型。和微调比，RAG 更新便宜、能引用。

## 追问

**和 Agent 的关系？**

检索可以是 Agent 的一个 tool（「需要时再搜」），也可以是 Chain 里固定的第一步。不是所有 RAG 都要上 Agent。

**幻觉还会有吗？**

会。资料不相关或 Prompt 不硬，模型照样编。要用引用、拒答、评估（有没有 ground on docs）。
