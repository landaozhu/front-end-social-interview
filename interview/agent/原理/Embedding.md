Embedding 把文本变成 **固定长度的浮点向量**，让「意思相近」的句子在空间里距离更近。RAG、语义检索、去重、聚类都靠它，不是靠关键词是否相同。

```text
"怎么降幻觉" ≈ "如何减少模型编造"
两者向量夹角小；和 "今天天气" 夹角大
```

## 和 Chat 模型的区别

| | Embedding 模型 | Chat / 生成模型 |
|--|----------------|-----------------|
| 输出 | 向量 | 文本 / tool_calls |
| 用处 | 检索、相似度 | 回答、推理、调用工具 |
| 计费 | 通常按输入 token | 输入 + 输出 |

检索阶段用 embedding 模型；生成阶段用 Chat 模型。别用 Chat 模型的回答去当向量，也别指望 embedding 模型写文章。

## 在 RAG 里的位置

文档块预先 embedding 进向量库。用户问题当场 embedding，取最近邻。问题和文档必须用 **同一个 embedding 模型**，否则空间对不上。

换 embedding 模型 = 整库重刷。这就是为什么 embedding 选型要先定，不要天天换。

## 面试 60 秒

Embedding 是语义向量，用来检索相近文本。RAG 里文档和问题用同一套 embedding 模型，生成仍用 Chat 模型。它解决「字面不同、意思相同」，解决不了「资料里根本没有」。

## 追问

**相似度用余弦还是 L2？**

常见余弦或内积。选向量库默认的即可，关键是构建和查询一致。

**多语言 / 代码？**

要选声明支持该语言或代码的模型。用英文 embedding 去检索中文块，效果会差一截。
