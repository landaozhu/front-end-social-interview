# 监控平台性能指标怎么获取的

## 一句话

监控平台不自己「算页面快不快」，是**浏览器提供 Timing / Observer API，前端 SDK 采集后上报**，平台再聚合告警。

## 采集链路

```
浏览器 API（Navigation Timing / Paint / LCP / CLS…）
        ↓
前端监控 SDK（采样、裁剪、加业务维度）
        ↓
sendBeacon / fetch 上报
        ↓
监控平台聚合（分位点、页面、版本、机型）
```

## 核心指标怎么拿到

| 指标 | 怎么取 |
|------|--------|
| TTFB / DNS / TCP | `performance.getEntriesByType('navigation')[0]`（Navigation Timing Level 2） |
| FP / FCP | `PerformanceObserver` 观察 `paint`，或 `getEntriesByType('paint')` |
| LCP | `PerformanceObserver` 观察 `largest-contentful-paint`，取最后一次 entry |
| CLS | 观察 `layout-shift`，累加 `hadRecentInput === false` 的 `value` |
| FID / INP | 观察 `first-input` / `event`（需 polyfill 或 web-vitals） |
| 资源耗时 | `getEntriesByType('resource')`：JS/CSS/图片各自 duration |
| 长任务 | 观察 `longtask`（>50ms），用来解释卡顿 |

老代码里还有 `performance.timing`（Level 1），新项目优先 **PerformanceObserver + navigation entry**，更准、可增量。

## SDK 侧常见做法

1. **采样**：不是 100% 上报，按 uv/session 采样，降成本
2. **时机**：`visibilitychange` / `pagehide` 用 `navigator.sendBeacon` 补发，避免关页丢数
3. **维度**：路由、页面 ID、发布版本、机型、网络（`navigator.connection`）
4. **自定义**：业务埋点（接口 RT、首屏模块 ready）和 Web Vitals 分开，不要混成一个大盘糊弄
5. **SPA**：路由切换后要重新起 Observer / 重置 LCP 统计窗口，否则只剩首屏那一次

## 场景：选座 SDK 怎么做性能指标监控

通用 Web Vitals（FCP/LCP）只能说明「页开得快不快」；选座 SDK 是**强交互座位图**，还要盯**业务可交互时间**和**SDK 自身阶段耗时**，否则优化对不上瓶颈。

### 指标怎么定（通用 + 业务）

| 类型 | 指标 | 含义 |
|------|------|------|
| 通用 | FCP / LCP / TBT / longtask | 页是否卡、主线程是否堵 |
| 业务 | **选座可交互 TTI** | 从进入选座到用户能点座（座位图画完 + 关键数据就绪） |
| SDK 阶段 | `sdk_load` → `sdk_init` → `seat_render` → `interactive` | 拆开是包下载慢、初始化慢还是画布渲染慢 |
| 接口 | 场次/票档/座位图接口 RT | 串行 waterfall 一眼能看出来 |
| 体验 | 缩放/拖拽帧耗时、首次点座延迟 | 交互卡不卡，不只看首屏 |

一句话：**大盘用 Web Vitals，优化用阶段埋点；验收以选座可交互为准（例如 2s→1.3s）。**

### SDK 内怎么采

```
进入选座页 mark('seat_enter')
  → SDK 脚本开始加载 mark('sdk_load_start')
  → SDK ready / init 完成 mark('sdk_ready')
  → 座位图首屏渲染完 mark('seat_painted')
  → 可点座 mark('seat_interactive')  // 业务 TTI
各段 duration 上报 + 通用 PerformanceObserver
```

要点：

1. **用 `performance.mark` / `measure`**（或 SDK 自己的时间戳）打阶段点，比只报一个「首屏」好排查
2. **SDK 对外暴露钩子**：`onReady` / `onFirstPaint` / 宿主页订阅后再上报，避免宿主猜内部时机
3. **维度**：场次 id、座位规模（座位数档）、端（H5/小程序）、SDK 版本、网络、机型——大场馆和小剧场不能混一个均值
4. **采样 + sendBeacon**：同通用 SDK；关页补发，避免选完就走丢数
5. **小程序**：没有完整 PerformanceObserver 时，用业务 `Date.now()` 阶段点 + 主包/分包加载耗时；`setData` 次数/体积也可作辅助指标

### 和「只看 Lighthouse」的关系

webpack 升级会看 seat-area / select-seats 的 FCP/LCP/TBT；**选座业务优化验收**更信业务 TTI + 真机弱网。Lighthouse 偏实验室，阶段埋点偏线上 RUM。

### 简历挂钩说法

选座首屏优化前先度量：Network 看串行、Performance 看大包、**业务埋点看可交互**。优化（并行、分包、按需）后用同一套指标对比，**2s→1.3s**，不是只看开发者工具一次。

## 和「性能指标咋计算」的区别

- **咋计算**：指标含义、公式、好坏阈值（面试八股）→ [性能指标咋计算](../浏览器/性能指标咋计算.md)
- **监控平台怎么获取**：API → SDK → 上报 → 平台（工程落地）
- **选座 SDK**：在通用采集之上，加**业务 TTI + SDK 阶段 mark**，才能指导选座优化
