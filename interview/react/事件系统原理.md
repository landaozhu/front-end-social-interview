# React 事件系统原理（面试版）

## 和原生 DOM 事件有什么不同

- React 在多数场景下使用 **合成事件（SyntheticEvent）**：对原生事件做了一层包装，抹平部分浏览器差异，并提供统一的 `preventDefault`、`stopPropagation` 等 API。
- **事件委托**：在 React 17 之前，合成事件一般在 document 上做委托；从 **React 17** 起，根事件监听器挂到 **应用的根 DOM 容器**（例如 `createRoot` 挂载的节点）上，而不是 document，减少对全局 document 的占用、利于多版本 React 或微前端共存。
- **批处理（批更新）**：在 React 18 中，合成事件处理器内的 `setState` 等更新会参与自动批处理（与 `flushSync` 等例外行为相对），减少重复渲染。

## 捕获与冒泡

合成事件同样支持捕获阶段与冒泡阶段，写法与原生类似，例如 `onClickCapture` / `onClick`。

## 常见追问

1. **`e.nativeEvent` 是什么**：拿到底层原生事件对象。
2. **为什么有时要先 `e.persist()`（老代码）**：历史版本中合成事件对象会被复用，异步读取属性前需要 `persist`；新版本使用场景已减少，以当前文档为准。
3. **React 17+ 根容器变化的影响**：事件委托挂载点变化、与原生事件混用时监听顺序可能不同，排查 bug 时要注意监听绑在哪个节点上。

## 与「手写 EventEmitter」题的区别

手写 `on / once / emit / off` 属于 **发布订阅模式** 实现；本题侧重 **DOM 与 React 调度层** 上的事件封装与委托，两者答题维度不同。
