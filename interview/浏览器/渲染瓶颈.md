“浏览器渲染过程有哪些瓶颈？”

不是 URL 输入全过程。

一、先说整体渲染流程（必须先立框架）

浏览器渲染我一般分：

HTML Parse
↓

DOM Tree

CSS Parse
↓

CSSOM

DOM + CSSOM
↓

Render Tree

↓

Layout（Reflow）

↓

Paint（Repaint）

↓

Composite（图层合成）

一句话：

解析 → 构建 → 布局 → 绘制 → 合成

二、每个阶段在干嘛
1. HTML Parse → DOM Tree

浏览器解析 HTML。

例如：

<div>Hello</div>

变：

DOM Tree

类似：

html
 └ body
    └ div
瓶颈1：同步 JS 阻塞（高频）

例如：

<script src="huge.js"></script>

浏览器：

暂停 HTML 解析
执行 JS

因为：

JS 可能修改 DOM。

所以浏览器不能继续往后解析。

例如：

document.write()

会改 DOM。

优化
defer

HTML 解析完再执行。

<script defer>
async

下载完立刻执行。

适合：

统计脚本
广告脚本
code split

减小 bundle。

2. CSS Parse → CSSOM

CSS：

.red{
 color:red
}

变：

CSSOM Tree
为什么 CSS 会阻塞？

因为：

Render Tree 依赖 CSS。

浏览器必须知道：

颜色
大小
display
position

否则不知道怎么画。

所以：

CSS 会阻塞渲染。

但：

一般不阻塞 DOM 解析。

瓶颈2：CSS 文件过大

例如：

500kb css

影响：

首屏渲染
优化
critical css

首屏 CSS 内联。

非关键 css 延迟加载
删除无用 css
3. Render Tree

把：

DOM
+
CSSOM

合并。

生成：

Render Tree

注意：

不是什么节点都进 Render Tree

例如：

display:none

不会进入。

因为：

不渲染。

而：

visibility:hidden

会进入。

因为：

占位置。

4. Layout（Reflow）—— 最大瓶颈之一

也叫：

回流
重排

核心：

计算元素尺寸和位置。

例如：

浏览器算：

宽度
高度
left
top
margin
哪些会触发 layout？
DOM 增删
appendChild()
尺寸变化
div.style.width
窗口 resize
字体变化
读取布局属性（高频追问）

例如：

offsetHeight
clientWidth
scrollTop
为什么读取也会触发？

经典题。

例如：

div.style.width='100px'

console.log(div.offsetHeight)

浏览器原本想：

晚点统一 layout

你突然：

给我高度

浏览器只能：

强制立刻 layout。

叫：

Forced Synchronous Layout

高级词。

为什么 layout 贵？

因为：

可能连锁影响。

父元素变：

子元素位置变化
兄弟节点变化

整个树重算。

所以：

回流成本高。

优化方案（高频）
1. 批量修改 DOM

别：

for(){
 div.style.width
}

容易频繁回流。

先收集。

一次更新。

2. 避免频繁读写交替

坏例子：

div.style.width='100px'

div.offsetHeight

div.style.height='200px'

不断强制布局。

3. 用 class 替代多次 style
4. 减少 DOM 层级
5. Paint（Repaint）

绘制。

画：

颜色
背景
阴影
文字
border
什么触发 repaint？

例如：

color:red

布局没变。

只是颜色变。

只 repaint。

什么最耗 paint？
box-shadow
filter: blur
大图片
大面积渐变
border-radius
优化

减少复杂样式。

图片压缩。

避免超复杂阴影。

6. Composite（图层合成）

最后：

多个 layer：

GPU 合成

显示。

GPU 加速

例如：

transform
opacity

通常：

只 composite

不会：

layout
paint

所以动画更流畅。

高频题

为什么：

transform 比 top 好？

因为：

top/left

触发：

layout
paint
composite
transform

通常：

composite

成本低。

60fps 更容易。

三、回流 vs 重绘（超高频）
回流（layout）

布局变。

例如：

width
height
display
margin

成本：

高。

重绘（paint）

布局不变。

例如：

color
background

成本：

较低。

一句话：

回流一定重绘，重绘不一定回流。

四、渲染过程中的核心瓶颈（重点）

真正面试说：

我会重点关注三类瓶颈。

1. JS 阻塞

大 bundle。

长任务。

阻塞主线程。

2. Layout

频繁回流。

强制同步布局。

3. Paint

复杂样式。

大图。

复杂动画。
