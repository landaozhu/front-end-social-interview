# 内存泄漏怎么排查

母题：[前端内存泄漏](./前端内存泄漏.md)

25k 一面过关线：能说出 **同一路由进进出出，看堆能不能回到基线**；会用 **Heap snapshot / Comparison** 和搜 **Detached**；追问能分清 **泄漏 vs 故意缓存**，以及 **别把 console.log 钉住的对象当成泄漏**。

为什么堆只涨不降，见 [v8的垃圾回收机制](./v8的垃圾回收机制.md) 分点解释里的晋升。常见漏点见 [泄漏场景](./泄漏场景.md)。

---

## 步骤

1. **复现**：同一路由进 → 操作 → 离开，循环十几次。Performance 里 JS heap 若台阶上涨、回不到基线，再往下查。任务管理器只能当信号。
2. **Heap snapshot**：离开后拍一张，搜 `Detached`。两张快照 **Comparison**，看 count / size 只增不减的 constructor。
3. **对代码**：增长的是 listener、closure、Vue 实例还是业务 Map。对上没清的那一行。框架内部稳、只有业务对象涨，别甩锅 V8。
4. **误判**：DevTools 开着 `console.log` 大对象会把它们钉在堆上；生产日志不要 dump 响应式树。
5. **微前**：子应用切 10 次，heap 应回去。

能讲清「晋升到老生代之后 Comparison 里全是老对象」比会点按钮加分。

## 追问

**Q：怎么证明泄漏而不是正常缓存？**  
A：离开页面后堆应回基线（keep-alive 除外）。只增不减才是漏。

**Q：Comparison 看什么？**  
A：delta 为正且离开后还不掉的类型；Detached HTML；自己的组件名 / Map。

**Q：怎么证明不是框架的问题？**  
A：看涨的是业务 listener / 自己的类，还是 Vue/React 内部。业务涨就查没清的订阅。

**Q：微前切走后堆不回去？**  
A：查子应用自己挂的 timer、`window` 监听、全局 bus。qiankun 劫持的不一定覆盖你手写的那些。
