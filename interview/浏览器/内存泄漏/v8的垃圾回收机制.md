# V8 的垃圾回收机制

母题：[前端内存泄漏](./前端内存泄漏.md)

25k 一面过关线：按 **背景 → 整体 → 分点** 讲。先说清为什么不能整堆标记清除，再用几句概括 V8 现在怎么做，最后才拆新生代/晋升/老生代。一上来就晋升、写屏障，过不了。

---

## 1. 背景

回收要解决的事没变：JS 堆里 **已经用不到的对象** 得还回去。判断靠 **可达性**——从根出发（`window`、调用栈、还活着的闭包），顺着引用摸，摸到的留下，摸不到的回收。

最早、也最好懂的算法是 **标记清除**：摸一遍叫标记，摸不到的删掉叫清除。堆很小的时候，这样做没问题。和 **引用计数** 的对比、循环引用代码见 [标记清除和引用计数](./标记清除和引用计数.md)。

浏览器里 JS 堆会涨到几十、上百 MB，如果 **每次回收都对整堆做一遍标记清除**，会有两件事过不去：

1. JS 必须停下来等它扫完（Stop The World）。主线程还要处理输入和渲染，停太久页面就卡。
2. **大部分对象活完一个函数、一次 render 就死了**（分代假说）。整堆扫一遍，大量时间花在确认「这些早就死了的对象确实死了」，划不来。

有这两条，才需要后面那套，而不是把标记清除整个扔掉。

---

## 2. 整体描述

V8 **按对象活了多久把堆切开**，不同区用不同算法：

- **新生代**：刚分配的对象，空间小。用 **复制（Scavenge / Minor GC）**——只把还活着的拷到另一半，剩下整区扔掉。短命对象最多，这样最便宜。
- **老生代**：活过几次才进来，空间大。这里继续 **标记清除，碎片多了再整理（Major GC）**。
- 老生代一旦整区标记仍会卡住 JS，所以再加 **增量、并发**，把一次长停顿拆碎。

一句话：**标记清除没过时，它变成老生代的活；年轻的用复制先挡掉。不是「JS = 标记清除」。**

DOM 节点在渲染引擎里，不在 V8 堆；JS 包装对象在 V8。JS 还握着节点，节点也销毁不了，见 [泄漏场景](./泄漏场景.md)。

下面把整体里的每一块拆开。

## 3. 分点解释

### （1）可达性具体怎么走

从根往外摸。还能摸到 = 还被用，不能收。摸不到 = 垃圾。

泄漏不是 GC 坏了，是你以为不用了，从根上还能摸到（监听、timer、全局变量还指着它）。`WeakMap` 的 key 不算单独把对象钉死，只被 WeakMap 握着仍可收。

「标记清除」里的「标记」，就是这次摸一遍。它是老生代算法里的一步。

### （2）切开之后三个区

| 区 | 谁住这儿 | 怎么收 |
|----|----------|--------|
| 新生代 | 刚 new 出来的，量级数 MB | 复制，Minor GC |
| 老生代 | 活了几次的 | 标记清除 / 整理，Major GC |
| 大对象区 | 一块就接近 1MB 级的 | 不在新生代里来回搬 |

年轻的死得快，用便宜的复制；老的活得多，复制划不来，才用标记。

### （3）新生代：From / To 复制

新生代两半：**From** 和 **To**。新对象只在 From 上分配。From 满了就 Minor GC：

1. 从根出发（还要带上「老对象指向新对象」的那些槽，见写屏障）
2. 活着的 **拷贝**到 To，紧挨着放
3. From 里剩下的当死的，整区丢弃
4. From / To 对调，下一轮接着在新的 From 上分配

只搬活人。新生代里死人占绝大多数，所以比整堆标记快。后来还有并行复制，一面说「可以多线程扫」即可。

### （4）活久了：晋升

对象不是永远待在新生代。Minor GC 活下来会记年龄，到阈值（常说两次）就 **晋升**到老生代。太大、To 里塞不下的，也可能直接去老生代。

之后它不在新生代了，Minor GC **扫不到它**。只能等 Major GC。如果引用一直在，Major 也认为它活着，堆就台阶往上、回不来——这就是泄漏在图上的样子。

晋升是整体里「年轻区 → 年老区」那一跳，不是单独黑话。

### （5）老指新：写屏障

Minor GC 如果只从 `window` 和栈出发，会漏掉「只有某个老对象还指着的年轻对象」，误当成死的。所以老对象写成「指向新对象」时要 **记账**（写屏障 → remembered set）。Minor GC 从这些槽接着扫。

一面一句：**老指新要记账，否则年轻对象会被误杀。** 增量标记也靠写屏障维持三色正确。

### （6）老生代：标记、清除、整理

老生代对象多、活得长，不能靠复制（活人太多，搬不动）。

1. **标记**：从根走可达性。三色：白=还没访，灰=待扫，黑=扫完。
2. **清除**：白的回收。中间会留下洞（碎片），大对象可能塞不进去。
3. **整理**：碎片多了，把活人往一端搬，更新指针。比清除贵，不是每次都做。

所以「标记清除」只描述老生代的主路径；前面还有一整段新生代复制。

### （7）停顿：增量 / 并发

一次把老生代标完，JS 要停很久。V8 后来：

- **增量标记**：标记和 JS 穿插
- **并发标记 / 并发清除**：放到辅助线程
- **惰性清除**：标完先干活，空闲再一点点把洞还回去

收束：**年轻复制、年老标记；停顿靠增量/并发拆掉。**

### （8）接到泄漏

引用不掰断 → 每次 Minor 都还活着 → 晋升老生代 → Minor 帮不上忙 → Major 也收不掉。

防法在 [泄漏场景](./泄漏场景.md)，查法在 [怎么排查](./怎么排查.md)。

## 追问

**Q：现在还讲标记清除吗？**  
A：先讲背景：整堆标会停、对象大多短命。再讲整体：年轻复制、年老才标记。标记清除没废，是老生代的活。

**Q：新生代为什么用复制？**  
A：活的少、死的多，搬活人更便宜。半区浪费一半空间，但新生代本来就小。老生代活人多，复制划不来。

**Q：晋升是什么？**  
A：Minor GC 活下来的对象搬去老生代。泄漏引用不拆，就会晋升，之后只有 Major GC 管得着，且仍收不掉。

**Q：写屏障干什么？**  
A：老对象指向新对象时记账，Minor GC 才不会漏扫、误杀。

**Q：增量 / 并发解决什么？**  
A：Major 一次标完停太久。拆开跟 JS 穿插，或放到辅助线程。

**Q：DOM 在不在 V8 堆？**  
A：节点在渲染引擎；JS 包装在 V8。JS 引用还在，节点也销毁不了。
