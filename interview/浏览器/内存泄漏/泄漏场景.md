# 内存泄漏场景

母题：[前端内存泄漏](./前端内存泄漏.md)

25k 一面过关线：能自己数出 **监听 / 定时器 / 全局钉住 / 游离 DOM**；能对上 Vue `beforeUnmount`、React `useEffect` cleanup；追问必须拆穿 **「闭包一定泄漏」**。

回收机制见 [v8的垃圾回收机制](./v8的垃圾回收机制.md)。

---

## 常见类型

| 类型 | 典型写法 | 防 |
|------|----------|-----|
| 事件 | `window.addEventListener`、bus `$on`、WS `onmessage` | 同一函数引用 `remove` / `$off` / `close` |
| 定时器 | `setInterval` 轮询库存、倒计时 | `clearInterval`；`onHide` / unmount 必清 |
| 全局钉住 | `window.xxx`、模块顶层 `Map` 当缓存 | 上限 / 按路由清；对象 key 才考虑 `WeakMap` |
| 游离 DOM | JS 握着已 `removeChild` 的节点 | 引用置 `null`，不要长期存 DOM |
| 框架 | Vue 自定义事件、React `useEffect` 没 cleanup | 对 `beforeUnmount` / effect `return` |

选座、上单：`onShow` 开的轮询，离开页面不停就又漏又脏数据。微前子应用切走，自己挂的 `window` 监听 / timer qiankun 不一定替你收。

闭包会延长寿命，这是特性。泄漏要另有一根还在的引用。脱口「闭包等于泄漏」是错的（腾讯面过）；老 IE 的 DOM 循环引用不要再背。

---

## 框架里怎么写

```js
onBeforeUnmount(() => {
  window.removeEventListener('resize', onResize) // 必须是 add 时那个函数
  clearInterval(timer)
  bus.off('pay-ok', onPay)
})
```

Vue 2 钩子是 `beforeDestroy`。React 对 `useEffect` 的 `return`。匿名函数 add 再写一个匿名 remove，摘的不是同一份，监听还在。

keep-alive 是故意缓存，不算漏；`deactivated` 里 interval 也要停。

这些引用不掰断，对象会在新生代活过几次后 **晋升老生代**，Minor GC 再也帮不上忙。

## 追问

**Q：闭包一定泄漏？**  
A：否。把握着闭包的那根引用去掉就能收。

**Q：remove 不掉？**  
A：不是同一个函数引用。保存成变量，或 `AbortController` 一把断。

**Q：WeakMap 当接口缓存？**  
A：key 必须是对象。用户 id 字符串只能普通 Map + 上限。

**Q：定时器为什么狠？**  
A：浏览器握着回调，闭包里的组件、列表、DOM 全活着，还会继续请求。

**Q：keep-alive 算泄漏吗？**  
A：故意缓存不算。真漏是以为销毁了其实还在。
