# 标记清除和引用计数

母题：[前端内存泄漏](./前端内存泄漏.md)

V8 怎么分代见 [v8的垃圾回收机制](./v8的垃圾回收机制.md)。本题只讲两种 **最基础的回收算法**：引用计数、标记清除——各自怎么做、优缺点、用代码能走一遍。

25k 一面过关线：能用自己的话讲清 **计数归零就释放** vs **从根摸一遍再删摸不到的**；必须能举 **循环引用** 把引用计数卡死；追问能对比停顿、碎片、和现在 V8 老生代的关系。只说「JS 用标记清除」不够。

---

## 1. 背景

回收要回答同一件事：这块内存还有没有人用。两条经典路：

| | 引用计数 | 标记清除 |
|--|----------|----------|
| 问法 | 还有几根指针指着我？ | 从根还能摸到我吗？ |
| 何时动手 | 计数变成 0 **立刻**释放 | 等一次 GC，统一扫 |

早期 IE 的 COM/DOM、Python 主路径走引用计数；现在的 V8 **主路径不是计数**，老生代才是标记清除这一路。面试常把两套对比着问。

---

## 2. 引用计数

### 怎么做

每个对象身上挂一个整数 `ref`。多一根指针 **+1**，少一根 **-1**，到 0 就立刻释放。

四种情况是四件独立的事，下面 **每个例子单独看**，不要串在一起。

公共的两下：

```js
function addRef(obj) { obj.ref += 1 }   // +1
function release(obj) {                 // -1，到 0 就 free
  obj.ref -= 1
  if (obj.ref === 0) console.log('free', obj.name)
}
```

#### 例子 1：赋值

`x = a` 就是多一根指着 a；再写成 `x = null` 就是把这根拿掉。

```js
const a = { name: 'a', ref: 0 }
let x = null

x = a
addRef(a)    // +1  x 指着 a     a.ref = 1

x = null
release(a)   // -1  x 不再指 a   a.ref = 0 → free a
```

#### 例子 2：当参数

函数一进来，参数占一根；函数一返回，这根没了。

```js
const a = { name: 'a', ref: 0 }

function fn(obj) {
  addRef(obj)     // +1  参数 obj 指着 a     a.ref = 1
  // ... 用一下 obj
  release(obj)    // -1  函数结束，参数没了   a.ref = 0 → free a
}

fn(a)
```

外面如果还有变量指着 a，函数返回后 `ref` 只会从 2 变回 1，不会 free。这个例子里外面没人指，所以返回就 free。

#### 例子 3：放进数组

`push` 等于数组多了一根。

```js
const a = { name: 'a', ref: 0 }
const list = []

list.push(a)
addRef(a)    // +1  list[0] 指着 a     a.ref = 1
```

这时还没有 free，因为数组还握着。

#### 例子 4：从数组 / 变量上拿掉

上一例的反面：`pop` 或 `x = null`，少一根。

```js
const a = { name: 'a', ref: 1 } // 先假定数组已经指着它
const list = [a]

list.pop()
release(a)   // -1  数组不要了     a.ref = 0 → free a
```

规则就这一句：**谁多指一下就 +1，谁不再指就 -1。** 四种情况只是「谁」不同。

### 致命缺点：循环引用

两个对象互相指着，外部已经不要它们了，计数却到不了 0。

```js
const a = { name: 'a', ref: 0, child: null }
const b = { name: 'b', ref: 0, child: null }

a.child = b
addRef(b)    // +1  a 指着 b     b.ref = 1

b.child = a
addRef(a)    // +1  b 指着 a     a.ref = 1

// 外面已经没有变量指 a、b 了，但：
// a.ref 仍是 1（被 b 指着）
// b.ref 仍是 1（被 a 指着）
// 谁也到不了 0，free 打不出来
```

老 IE 里 DOM 节点和 JS 闭包互相引用，就是这条：页面关了计数还不是 0，泄漏。腾讯面过「闭包等于泄漏」——错在把这个历史 bug 当成闭包本身。现在的 V8 用可达性，**循环只要从根摸不到，照样能收**。

Python 主路径仍是引用计数，另外再跑一遍循环检测补刀。JS 引擎没有把计数当主算法。

### 优点 / 缺点

| | 说明 |
|--|------|
| 优点 | 不用的立刻还；停顿摊在每次赋值上，没有「突然卡一下扫整堆」；实现直观 |
| 缺点 | **循环引用收不掉**；每次赋值都要改计数，写多读多时很贵；多线程还要原子加减；大图 `ref` 到 0 会连锁释放，也可能一次停很久 |

## 3. 标记清除

### 怎么做

不数有几根指针。到了 GC 时机：

1. **标记**：从根出发 DFS/BFS，摸到的打上「活」
2. **清除**：堆上没被标到的，当成垃圾删掉

```js
function create(name) {
  return { name, marked: false, child: null }
}

function mark(obj) {
  if (!obj || obj.marked) return
  obj.marked = true
  mark(obj.child)
}

function sweep(heap) {
  const alive = []
  for (const obj of heap) {
    if (obj.marked) {
      obj.marked = false // 清标记，留给下次
      alive.push(obj)
    } else {
      console.log('free', obj.name)
    }
  }
  return alive
}

function gc(heap, roots) {
  for (const r of roots) mark(r)
  return sweep(heap)
}

const a = create('a')
const b = create('b')
a.child = b
b.child = a // 循环

let heap = [a, b]
heap = gc(heap, [a]) // 根还握着 a → a、b 都摸到，谁也不 free

heap = gc(heap, []) // 根没了 → 循环也 free
// free a
// free b
```

和引用计数的差别：最后一次根是空的，循环照样清掉。因为问的是「从根摸得到吗」，不是「计数是不是 0」。

### 清除之后的碎片

删掉的对象在堆中间留下空洞。后面要分配一块大的，可能每个洞都不够，明明总空闲还很多。所以后面常接 **标记整理**：把活人往一端搬，更新指针，空洞挤掉。V8 老生代就是标记清除，碎片多了再整理。

标记期间一般要停 JS（Stop The World），否则一边扫一边程序还在改指针，会标错。

### 优点 / 缺点

| | 说明 |
|--|------|
| 优点 | **能收循环引用**；普通赋值不用维护计数；和「从根摸」的心智一致，也是理解泄漏的那套 |
| 缺点 | 不能立刻释放，要等一次 GC，峰值内存更高；一次标记可能停很久；清除留下 **碎片** |

整堆每次都标记清除，就是 [v8的垃圾回收机制](./v8的垃圾回收机制.md) 背景里那条走不通的路。V8 只把这条留给老生代，并用增量/并发把停顿拆碎。

## 4. 放在一起看

| | 引用计数 | 标记清除 |
|--|----------|----------|
| 回收时机 | 计数到 0 立刻 | GC 时批量 |
| 循环引用 | 收不掉 | 根摸不到就能收 |
| 赋值开销 | 每次 `++` / `--` | 几乎没有 |
| 停顿 | 平时摊开，连锁释放也可能猛 | 一次 STW，堆越大越明显 |
| 碎片 | 看分配器 | 清除后常见，往往要整理 |
| 现在谁用 | Python 主路径；老 IE DOM | V8 老生代；理解 JS 泄漏用这一套 |

面试怎么收：业务里说的泄漏（监听没摘、timer 没清），用的是 **标记清除这套可达性**——根还摸得到。不是引用计数没减到 0。只有被问「还有一种算法」或「为什么老 IE 闭包泄漏」才把计数和循环拎出来。

## 追问

**Q：引用计数为什么处理不了循环？**  
A：互相指着时双方 `ref` 至少是 1。外部不要了，谁也不会先变成 0，谁也不触发释放。

**Q：标记清除怎么处理循环？**  
A：不问互相指没指，只问根摸不摸得到。根断了，环上的点都摸不到，一起清。

**Q：V8 用哪个？**  
A：主路径不是引用计数。新生代复制，老生代标记清除（再整理、增量/并发）。见 V8 那篇。

**Q：为什么不纯用引用计数？**  
A：循环、赋值开销、多线程原子计数。浏览器 DOM 和 JS 对象很容易互相指，计数当主算法会把泄漏变成常态。

**Q：标记整理和标记清除差在哪？**  
A：清除只删、留洞；整理把活人搬到一起，解决碎片，但要改指针，更贵。
