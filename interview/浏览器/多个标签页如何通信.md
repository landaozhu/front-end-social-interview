常见跨标签页通信方式
1. localStorage + storage 事件

// Tab A 写入
localStorage.setItem('msg', JSON.stringify({ type: 'update', data: 123 }));
// Tab B 监听（注意：只有「其他标签页」写入才触发，本 tab 写入不会触发）
window.addEventListener('storage', (e) => {
  if (e.key === 'msg') console.log(JSON.parse(e.newValue));
});
原理：同源标签页共享 localStorage，跨 tab 写入触发 storage 事件
场景：简单状态同步（登录态、主题切换）
限制：不能传对象引用；有大小限制（约 5MB）；本 tab 不触发
2. BroadcastChannel（更现代）

const channel = new BroadcastChannel('my_channel');
channel.postMessage({ hello: 'world' });
channel.onmessage = (e) => console.log(e.data);
同源标签页/iframe/worker 广播，API 更干净
场景：多 tab 实时通知
3. window.postMessage

跨窗口/iframe/标签页（需拿到 window 引用，如 window.open 返回的窗口）
场景：iframe 与父页、popup 窗口通信
4. SharedWorker

多个 tab 共享同一个 Worker 线程，通过 port 通信
场景：共享连接、统一计时器
5. WebSocket / 后端中转

各 tab 连同一服务器，服务端广播
场景：实时协作、聊天
6. Service Worker

SW 作为中转，各 tab 与 SW 通信，SW 再广播
场景：PWA、离线缓存 + 跨 tab 协调
