# 公司档位与出题天花板

按「这司会不会问」定天花板，再叠 JD 关键词。档位只决定问什么，不决定问几道——题量不封顶。

## 档位

| 档 | 例子 | 必压 | 几乎不问 |
|----|------|------|----------|
| 小厂 / 早期创业 / 外包 | 不知名、20 人、纯业务外包 | URL 输入过程、闭包、原型、防抖节流、跨域、Vue 生命周期 | 源码、TS 高级、XSS 深度、微前端、Hard 算法 |
| 内容社区中厂 | 知乎、小红书、B 站 | XSS/CSRF、TS 高级、Vue/React 源码、性能 | 过浅 HTML/CSS、居中、盒模型（开场最多一问） |
| 电商 / 本地生活 | 得物、拼多多、猫眼 | 首屏、缓存、长列表、工程化、微前端（简历有再深挖） | 纯算法竞赛、内容安全深度 |
| 业务中厂 / 数智化 | 杭州 25～35k 业务前端、双端 + 跨端 JD | Vue/React **核心原理**、C 端性能（首屏/渲染/弱网）、TS、Webpack/Vite、Taro/UniApp、组件化 | XSS 深挖、微前端（JD 没写就跳）、Hard 算法 |
| 大厂 | 字节、阿里、腾讯、美团、快手 | 源码更深、中等算法、高质量手写、项目深挖 | 太基础的题当开场最多一问 |
| ToB / 金融 | 银行、保险、企业服务 | 安全、兼容、权限、工程规范 | 花哨源码细节 |

未给公司名、只给 JD：用薪资 + 年限 + 栈推断档位。杭州 25～35k × 5 年以上 × Vue/React 原理 = **业务中厂**，不要按小厂只问 URL。

## JD 关键词 → 抬档

| JD 出现 | 抬哪些 | 简历没写时 |
|---------|--------|------------|
| Vue / React + **核心原理** | vue、react 源码级 | 仍要考，这是任职要求 |
| TypeScript | ts 高级类型、泛型、重载 | 仍要考 |
| 首屏 / 弱网 / 渲染 | performance、browser | 用项目数字答 |
| Webpack / Vite | engineering | Vite 单独原理最高中等深度 |
| Taro / UniApp / 小程序 | 跨端（题库可没有，照样出） | 结合简历微信小程序 |
| 组件化 / 重构 / 架构 | 组件库、模块划分、一次重构 | 二面更深，一面也要能讲 |
| CI/CD | 流程级了解 | 不要当 P0；JD 写了就准备 1 问 |
| 微前端 / qiankun | 仅 JD 或简历有才深挖 | JD 没写 → 跳过 |
| 安全 / XSS | security | 非内容社区不要压太多 |

## 几面

| 轮次 | 比重 | 代码 |
|------|------|------|
| **一面（默认）** | 原理 + 网络/性能 + 框架 + TS + 工程化 | **必须穿插手写**（防抖节流、深拷贝、Promise、并发、hooks/响应式相关） |
| 二面 | 项目 owner、架构、C/B 端差异、重构决策 | 1 道更难手写或中等算法；八股减少 |
| 三面 / 总监 | 方案、带人、故障、排期 | 代码可有可无 |

用户说「二面」「三面」才切轮次；没说就按一面，且不要整场都是口述。
