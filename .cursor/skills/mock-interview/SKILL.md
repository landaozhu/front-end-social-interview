# 一面模拟（整场 13 母题 · 25k 达标才打 ✓）

## 场次结构

| 类型 | 数量 | 要求 |
|------|------|------|
| 八股文 | **10** | **必须覆盖** 工程化、Vue、React、Node、网络、TS、原理、微前端（8 方向各至少 1 题，另 2 题加深） |
| 阅读代码 | **1** | `interview/阅读代码题/*.js` |
| 手写代码 | **2** | `interview/handwritten/` |
| **合计** | **13** | 母题，不含追问 |

出题顺序：原理 → 网络 → Vue → React → TS → Node → 工程化 → 微前端 → 2 道加深 → 阅读 → 2 道手写。

**原理**：只出 Vue / React / Webpack 的实现原理（响应式、Fiber / 虚拟 DOM、编译优化、HMR、打包流程等）。禁止浏览器、Performance、JS 基础当原理开场。Vue / React / 工程化槽仍从各自目录补其他题，不与原理槽抽同一道。

**工程化里的 Webpack**：按 [`interview/webpack/README.md`](../../../interview/webpack/README.md) **从上到下**取题。这个顺序就是高频顺序，禁止在 Webpack 题里随机跳。

- 只认 README 里指向本地 `.md` 的链接。当前顺序：从零配置 → 常用配置 → 提高打包速度。外链（原理文章、循环依赖）不进抽题。
- 往下走时跳过：当天已经做过、已「不再提问」、以及 **✓ 且还没到期** 的题。
- 未测和 ✗ 算还没稳住，排在更靠后的已会题前面。所以清单第一道还没学会时，工程化槽就出这一道，不跳到后面的冷门 Webpack 或 Vite。
- 清单上的题都稳住了（✓ 且未到期，或当天已考过），工程化槽才回到原来的池子（Vite、未写进 README 的 Webpack）。
- 其他槽若抽中 Webpack，也改成同一池里 README 最靠前的那道。清单还没走完时，不拿打包流程、HMR、灰度发布、TerserPlugin 这类清单外的题来充数。

必考 8 方向优先抽 **P0/P1**，没有再降到 P2/P3。Webpack 清单题不受这条随机降级影响，顺序优先。

**禁止**把后续题目提前告诉候选人。

```bash
node .cursor/skills/mock-interview/scripts/pick-interview.js
```

## 是否学会规则

| 结果 | 是否学会 | 首次学会 / R 列 | 遗忘曲线 |
|------|----------|-----------------|----------|
| 得分 ≥ 及格线 | **✓** | 写入日期 | ✅ |
| 得分 < 及格线 | **✗** | **清空** | ❌ |
| 未测 | **空** | 无 | ❌ |

✗ 仅表示「考过未达标」，不是冲刺池。

**及格线**：P0/P1 ≥ **6**；P2/P3 ≥ **5**。打 ✓ 细则见 [`spaced-review/scoring.md`](../spaced-review/scoring.md)：**6 分必须是追问之后的分**；半截答案或追问挂了不能打 ✓。

抽题（整场 **80% 已通过 ✓ · 20% 未通过 ✗**，未测不抽）：

- 已通过优先抽**到期复习**；到期没有再抽其他已通过。
- **8 个必考方向**：该方向有已通过 → 抽已通过（到期优先）；没有才抽未通过。两者都空才用未测兜底覆盖。
- **加深题和手写**：把整场未通过补到约 **20%**；已够则只抽已通过。

**当天已经做过的题（达标或未达标）当天绝不再抽。**  
**已打「不再提问」的题永不抽**（须用户主动说才打钩）。

## Agent 流程

### 1. 抽一整场 → 只公布规则 → 出第 1 题

开场只说：本场 **13 母题**（10 八股覆盖 8 方向 + 1 阅读 + 2 手写），约 70～90 分钟。然后立刻问第 1 题。

### 2. 每题：回答 → 追问 → 打分 0～10（再纠正）

- 八股 / 阅读：**必须** 1～2 个中位数追问（为什么 / 机制 / 易混点）。追问不算母题。第一口不完整时禁止直接打分。
- 分不清「真会」还是「没说出来」→ 只准追问确认。追问后关键机制仍说不清 → 最高 5，打 ✗。
- 手写：主路径能跑后再追 1 个常见边界；不要求所有边界。跑不通 → ≤4。
- 不抠源码行号、冷门 API。中位数面试官不会问的细节漏了，不影响 ✓。

### 3. 立刻写回（阅读代码跳过）

```bash
node .cursor/skills/mock-interview/scripts/mark-question.js "<question.id>" --score=<得分>
```

告知本机：

```
📊 得分：7/10（及格线 6）
✅ 已打 ✓ · 首次学会 2026-08-26 · R0→R1
```
或
```
📊 得分：3/10（及格线 6）
🔴 已打 ✗ · 未学会（无日期记录）
```

然后出下一题，直到 13 题结束。

### 4. 整场汇总

- 逐题得分（标方向 / 阅读 / 手写）
- 平均分、及格数 / 已打分题数
- **通过概率**（25k · 中大厂一面）：平均分 ≥7 且 P0 全及格 → 75%+；平均分 6～7 → 50～70%；平均分 <6 或 P0 大面积不及格 → <50%

## 禁止

- ❌ 不带分数打钩
- ❌ 未达标打 ✓
- ❌ 没追问就打 ✓（第一口不完整时）
- ❌ 追问不会 / 空白仍打 ✓
- ❌ 打 ✗ 仍写首次学会或 R 列
- ❌ 八股覆盖不全就开场（`coverageComplete` 必须为 true）
- ❌ 把 13 道题一次性抛给候选人
- ❌ 用浏览器 / Performance / JS 基础充当「原理」开场
- ❌ Webpack 题不按 `interview/webpack/README.md` 从上到下，改成随机抽
