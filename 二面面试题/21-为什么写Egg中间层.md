# 为什么写 Egg.js 中间层？

## 30 秒版

不是为了转后端，是**缩短联调排期**。上单 2.0 部分 mapi/中间层用 Egg 重构，前端能自己改接口聚合和字段适配，不等后端排期。主力仍是前端，能独立搞定中小型 Node 接口。

## 2 分钟版

**场景**  
- 新上单 2.0 前后端字段 1.0/2.0 并存（如销售计划倒计时 C 端不展示 — 字段未对齐）  
- 复制场次后默认销售计划：前端 + **Node 创建项目时建默认计划** 联调  

**Egg 选型**  
- 猫眼 B 端栈已有 Egg/Koa 生态  
- 与范特西 Vue3 前端同仓库或邻近，联调快  

**你做什么**  
- 部分接口重构、字段转换、草稿逻辑  
- 减少「前端 mock 两周等后端」  

**边界**  
- 复杂事务仍后端主 R  
- 我负责**为前端交付服务的中间层**，不是 DBA  

**对比携程**  
- Java BFF 做价格下沉、地图围栏 — 同一思路：**离前端近的一层自己掌控**
