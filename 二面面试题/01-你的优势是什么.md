# 你的优势是什么？

## 考察点

- 能否用**业务 + 技术 + 结果**概括自己，而不是堆形容词
- 20k 期望：体现**完整链路**经验，且**说的都能扛追问**

---

## 30 秒版（开场必背）

我有 **C 端开发 + B 端供给** 双线经验。猫眼 C 端参与过演出**列表、详情、下单、订单列表**等页面的开发和迭代，H5 和小程序都有接触。B 端主要是**运营平台和上单系统**的日常开发维护；其中 **上单 2.0 重构深度参与**——条件退、销售计划、蓄水，以及 qiankun + Vue3 选型。工程上主导 **webpack 编译提速**、**灰度接入**，页面性能有落地数据（首屏约降 50%+、编译约提 60%）。

---

## 2 分钟版（STAR 展开）

### 1. 业务：说实话，B 端比 C 端深

**C 端（猫眼演出）—— 开发面广，不包装成业务专家**  
- 参与 **list / detail / order / orderlist** 等页面的需求开发和迭代，H5 + 小程序  
- **不对外说「熟悉从浏览到支付的全链路业务状态」** — 各页面分工不同，我只对自己做过的模块能讲到细节  
- 选座相关：参与过票档、多场次跳转、日历适配、页面性能等，**座位图 SDK 不是我对接的**  
- 多端主要是容器差异、联调、发布，不是全链路业务 owner  

**B 端（猫眼）—— 日常维护 + 一个深度项目**  
- **日常**：**运营平台**（如七里香等 B 端后台）和**上单系统**的需求开发、迭代维护  
- **深度参与的项目**：**上单 2.0 重构**（不是 B 端只有这一个，但这是能展开讲的项目）  
  - 参与 qiankun + Vue3 选型评审  
  - 负责条件退、销售计划、蓄水等模块开发与联调  
  - 部分 Egg.js 中间层  
- **口径**：B 端整体是**熟悉维护**；复杂逻辑和踩坑**集中在上单 2.0**  

**一句话价值**：C 端多页面开发经验；B 端有运营/上单日常交付，**上单 2.0 重构能讲到模块级细节**。

### 2. 深度：有数字、能追问

| 方向 | 做了什么 | 结果 |
|------|----------|------|
| 页面性能 | 串行改并行、分包、按需加载（含选座页等核心页） | 首屏约 **2s → 1.3s** |
| webpack | 2→4 分步升级 | 首次编译 **50s→20s**，热更新 **15s→4s** |
| 灰度 | 网关迁 WebStatic，内外灰 | 小流量验证后再全量，降低发布风险 |
| B 端首屏 | 范特西 userMenu 预加载 | 约 **400–500ms** |

> 携程、宏波等更早经历：**简历里有，开场不主动提**，对方问到再答。

### 3. 工程化（只讲扛得住的）

- **webpack 升级、灰度发布**：我独立负责过，能讲步骤和踩坑  
- **Umi 升级**（七里香 B 端）：编译打包提速，有对比数据  
- **Code Review**：参与组内规范和评审流程，不是从零写制度  
- **eslint**：只是**基础配置**，不深问插件实现；面试不主动展开  

### 4. 协作（只讲猫眼近期）

- 上单/蓄水：PRD 改完集中评审，减少口头来回  
- 复杂模块：先列**自测 case** 再提测（条件退审核前后状态等）  
- 排期压缩、跨部门对齐：**单独题再答**，优势题里不展开

## 常见追问

**Q：你和普通 3 年前端的区别？**  
A：猫眼 **C 端多个交易页面、B 端运营平台/上单系统**都有开发维护经验；**上单 2.0 重构深度参与**，能讲模块细节；工程上 webpack、灰度、性能有负责人级落地。

**Q：你对演出购票业务熟吗？**  
A（诚实）：C 端按页面/模块开发，**不等于熟悉全链路业务**。B 端日常是运营平台和上单维护；**业务细节讲得最深的是上单 2.0 里我负责的模块**（条件退、销售计划、蓄水）。

**Q：B 端你主要做什么？**  
A：一块是**运营平台、上单系统**的日常需求和维护；另一块是 **上单 2.0 重构**，我深度参与，负责几个核心模块。运营平台以交付和稳定为主，重构项目能讲技术选型和复杂状态。

**Q：选座你负责到什么程度？**  
A（诚实）：参与页面迭代和性能优化、日历高度适配、多场次/票档相关前端逻辑；**座位图 SDK 是同事对接**，我不讲 SDK 内部实现。

**Q：eslint 插件做了什么？**  
A（若被问）：团队统一过基础 lint 规则，我参与配置；**没有深入写自定义 rule**，这块不是我最强项。

**Q：你最大的短板？**  
A：早期估时偏乐观；复杂模块（条件退、蓄水）教会我**先画状态矩阵再开发**，提测前按清单自测，减少返工。

**Q：为什么值 20k？**  
A：猫眼 **B 端运营/上单日常 + 上单 2.0 深度参与**；C 端多页面、多端经验；工程上有 webpack/灰度/性能数据。**说的范围可控。**
