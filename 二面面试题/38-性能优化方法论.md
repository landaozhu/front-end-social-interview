# 性能优化方法论？不要只会说懒加载

## 考察点

- 20k 要有**体系**，不是技巧堆砌
- 多项目数据支撑

---

## 30 秒版

四步：**度量 → 找关键路径 → 针对性改 → 数据验证**。C 端选座：并行+分包，2s→1.3s。携程地图：SSR+BFF 批量，4s→2s。B 端范特西：userMenu 预加载约 400–500ms。工程侧 webpack：编译 50s→20s。不做无关重构、不过早优化非热点。

---

## 2 分钟版

### 方法论

```
1. 度量（建立 baseline）
   ↓
2. 找关键路径（Network / Performance / 业务埋点）
   ↓
3. 假设 → 改动 → 对比
   ↓
4. 上线灰度 → 监控回滚
```

### 案例矩阵

| 场景 | 瓶颈 | 手段 | 结果 |
|------|------|------|------|
| 选座首屏 | 串行 API、大包 | 并行、分包、按需加载 | 2s→1.3s |
| 地图首屏 | SSR 后客户端 waterfall | BFF 批量、SSR 预取 | 4s→2s |
| 范特西 B 端 | userMenu 等 vendor | html 预请求 + 事件/ window 兜底 | ~400–500ms |
| webpack dev | loader 慢 | 2→4 分步升级 | 50s→21s |
| 小程序选座 | setData、包体积 | 分包、分区更新座位数据 | 配合 H5 整体优化 |

### 范特西 userMenu 预加载（细节）

- 问题：vendor 加载完后才请求 userMenu，阻塞首屏 ~1s  
- 方案：在 **index.html 原生 ajax** 预请求，数据挂 `window.menuData`  
- 兜底：html 失败则 js 里 axios 重试（复用错误处理）  
- 异步：html 未完成时 js 侧 `document.addEventListener('preGetUserMenuData')`  
- 后续：拆 vendor 包进一步优化  

### 原则

1. **用户指标优先** vs **开发体验**分开看（webpack 升 4 是后者）  
2. 优化要有 **before/after**  
3. 高风险优化走灰度  
4. 手势库、sourcemap 等**回归踩坑**说明性能优化要全链路测
