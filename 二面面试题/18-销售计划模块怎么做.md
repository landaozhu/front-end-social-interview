# 销售计划模块怎么做？和场次联动？

## 考察点

- B 端多模块联动 — tab 切换、草稿 vs 正式数据
- 审核前后行为差异

---

## 30 秒版

销售计划管理场次**怎么卖、何时卖、哪些渠道可见**。与场次增删改、复制、审核状态强联动。难点：**审核前用草稿可编辑，审核通过后读库且离开页要不误拦截**；新增/复制场次要同步可预约列表；条件退 tab 切换不能污染销售计划 store（深拷贝教训）。

---

## 2 分钟版

### 功能点

- 售卖渠道、销售计划卡片（新建/编辑/删除）  
- 每张计划：可售场次、可见场次、自定义可预约场次  
- 商家后台出票开关、提交审核  
- 与**条件退、座位、演出类型**等 tab 切换联动  

### 审核前 vs 审核后

| 状态 | 行为 |
|------|------|
| 未审核 | 草稿编辑；新增场次默认勾选；修改场次名称/开售时间 → 销售计划即时更新 |
| 已审核 | 读库渲染；新增/复制场次 → 弹窗勾选可预约；**离开销售计划不应误报「有改动」** |
| 复制场次 | 若无草稿需初始化默认销售计划（Node 侧创建项目时也建默认计划） |

### 典型 bug 与修复（真实素材）

1. **tab 切换改开售时间**（1205714）  
   - 切到履约 tab 判断条件退时，误把定时开售的 `onSaleTime` 改成生效时间  
   - 根因：**浅拷贝修改 store** → 深拷贝 + 判断条件修正（立即开售 vs 定时开售）  

2. **复制场次无默认销售计划**（1205963）  
   - 默认计划只在「创建场次」时初始化，复制不触发  
   - 修复：Node 创建项目即建默认计划；复制场次后若无草稿则初始化  

3. **新增场次未勾选可预约**（1205964）  
   - 「新增场次」= 接口列表 - 草稿列表；误更新草稿导致差集为空  
   - 修复：严格区分缓存场次与实时列表  

4. **保存按钮多次弹窗**（1206190）  
   - 高频点击未防抖 → 全量检查按钮防抖/loading  

### 自测 case 结构（面试可讲）

- 审核前/后 ×（新增/复制/删除场次）×（编辑销售计划/离开页面是否拦截）  
- 与条件退、座位 tab 来回切换  
- 保存、提交审核按钮高频点击

## 常见追问

**Q：为什么离开页要拦截？**  
A：未保存草稿丢失；但审核通过后读库场景**不应误拦**，否则 UX 极差 — 这是二轮 bug 重点。

**Q：草稿存在哪？**  
A：前端 store + 后端草稿接口；提审时才落库 — 具体以后端设计为准，关键是**前后端状态一致**。
