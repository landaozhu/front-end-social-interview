# eslint 和自研插件做了什么？

## 30 秒版

在存量 H5 项目**配置 eslint**，并开发**自研插件**拦截团队高频低级问题，配合 CR 规范「lint 不过不能提测」，降低 online bug。修改 eslint/package.json 属于 CR **高风险操作**，必须 Review 解释。

## 2 分钟版

**背景**  
- 历史 H5 代码风格不一，转正自评承认 bug 偏多  
- 团队推动 Code Review 规范落地  

**做法**  
1. 统一 eslint 配置 extends 团队规范  
2. **自研插件**：封装演出业务常见反模式（如危险的全局污染、错误生命周期用法 — 按你实际规则说 1–2 条）  
3. CI/提测前 lint 卡点  
4. 结合 AI 辅助自查（CR 规范允许）  

**与 CR 关系**  
- 自查阶段：必须过 lint  
- 合 Release：删 console 可能是**大问题**（可能藏空指针），不是小事  

**效果**  
- 重复类 bug 减少，Review 聚焦业务逻辑  
- 配置文件改动必须 PR 说明 — 避免误伤全队
