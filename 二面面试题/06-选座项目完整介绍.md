# 介绍选座项目 / 选座链路怎么做的？

## 考察点

- 能否讲清**业务背景 → 链路 → 你的职责 → 难点 → 结果**
- 二面会连环追问：多场次、状态、新旧上单差异、小程序

---

## 30 秒版

猫眼演出**核心转化链路**：用户选场次 → 票档 → 选座 → 下单支付。我参与新旧选座重构，负责票档页兼容、日历改造、**H5 + 微信小程序**交付；主导首屏性能 **2s→1.3s**；做了日历月/周 **swiper 高度自适应**。要处理单/多场次、售罄/延期/取消、固定套票等复杂规则。

## 2 分钟版

### S — 背景（为什么做）

- **用户**：旧选座体验差，覆盖率低，竞品差距大
- **商户/B 端**：更好选座体验 → 更多供给和 API 对接
- **业务目标**：详情到支付转化率从 **2.7% 向 3%+** 提升（转正材料）
- **技术目标**：Vue3 新选座页、SDK、日历屏效、多端一致

### T — 你的任务

| 模块 | 职责 |
|------|------|
| 票档页、确认订单页 | 兼容新旧链路（个人负责） |
| 日历 | 样式改造、屏效提升、npm 包更新 |
| 选座页 | Vue3 开发、性能优化（负责人） |
| 多端 | H5 + 微信小程序 |

### A — 链路（讲给面试官听）

**新上单路径**  
详情 → 点购票 → **单场次**直跳新选座页 / **多场次**先选票档页 → 日历选场次 → 新选座页 → 确认订单 → 支付

**票档页日历规则**  
- 日历模式：选「日期+场次」→ 进选座  
- 非日历模式：选场次 → 进选座  
- **不可点**：即将开售、售罄、延期、取消、缺货登记  
- 有未付款订单：需刷新状态  
- 日历展示：非正常状态下，标记各日期**最低价**

**旧上单差异**（体现你懂业务）  
- 旧：票档要选「场次+票档」才进选座；多分区先进选区页  
- 新：链路更短，单场次直达选座

**异常交互**  
- 不同排/分区选座：提示「您选择的座位不在同一排，请仔细确认」  
- 优惠券：商家后台配置，关联项目 id

### 难点

1. **状态多**：场次 × 票档 × 座位 × 库存，售罄/延期/取消随时变  
2. **多端**：H5 与小程序渲染、高度、包体积不同  
3. **性能**：座位图 + 多接口，首屏慢  
4. **日历**：月/周视图高度不固定 → swiper 抖动、遮挡

### R — 结果

- 外观和功能明显改善，支持复杂票型迭代  
- 首屏 **约 2s → 1.3s**（简历）  
- 日历高度方案落地 pre-ticket-v2、ticket-level-v2 等多个页面

## 常见追问

**Q：新旧选座怎么共存？**  
A：路由和入口按上单版本区分；票档页兼容两套跳转规则；逐步切新链路，避免一次全量。

**Q：项目里你最大的失误？**  
A：早期**估时偏乐观、PRD 未细读、自测不充分**（wiki bugfix 复盘）—— 后来提测前对照全量用例文档。

**Q：转化率目标达到了吗？**  
A：体验和能力明显提升；转化率受活动、库存等多因素影响，性能优化是必要条件之一，用首屏数据证明体验改善。
