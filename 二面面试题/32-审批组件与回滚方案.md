# 审批组件怎么设计？回滚方案？

## 30 秒版

宏波内部系统**多种审批**（请假、合同）共用审批壳，差异**配置化字段**。我设计**数据库表**存流程实例与节点状态；失败方案：提交失败不生成实例、中间节点驳回**回滚到上一状态**并留 audit log，避免半提交脏数据。

## 2 分钟版

**架构**  
- 审批壳：发起人、审批链、状态、附件  
- 类型插件：请假（天数/类型）、合同（金额/对方）  

**数据库**  
- 实例表 + 节点表 + 操作日志  
- knex + SQL Server 实现  

**回滚/失败**  
1. 提交前校验 — 失败不落库  
2. 审批驳回 — 状态机回到 draft/rejected，通知发起人  
3. 并发 — 乐观锁或状态校验防重复提交  
4. 线上异常 — 管理员可查看日志人工介入  

**产品优化**  
- 选人组件参照 163 邮箱 — 降低审批发起失败率  

**5000 人规模**  
- 性能：列表分页；索引审批人 id  
- 稳定性：高峰上午打卡+审批，监控慢查询
