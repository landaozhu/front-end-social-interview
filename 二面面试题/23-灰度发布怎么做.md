# 灰度发布怎么做？内外灰区别？

## 考察点

- 工程化 + 稳定性 — 负责人项目
- 能否讲网关、Node、前后端协同

---

## 30 秒版

存量 order-h5 **网关 peon 不支持灰度**，先迁 **WebStatic**，再接入**内灰+外灰**。内灰：参数 `isshowgray=true` 进灰度桶；外灰：按百分比分流。Node8→12，oceanus 配路径，前端把灰度参数传后端，**前后端同桶**。支持先内灰验证再外灰放量，降低全量事故。

---

## 2 分钟版

### 背景

- 演出 H5 购票，历史 Node/Gulp 老  
- 直接全量上线风险高（转正：「不保险，易造成线上事故」）  
- 个人负责 order-h5 **全部开发任务**  

### 步骤

1. **Node 8 → 12**：满足 WebStatic 迁移要求  
2. **网关迁移**：peon → WebStatic（oceanus 路径配置）  
3. **内灰**：开发/测试带 `isshowgray=true`，连灰度桶后端，正式环境验证  
4. **外灰**：按百分比用户进灰度桶 vs 主干，监控数据  
5. **前后端对齐**：前端传灰度标识，后端 follow 命中同桶 — 避免「前端灰度后端主干」  

### 发布流程（结合 CR 规范）

- 灰度发布 → 有问题另起分支 → test 环境 → 评审 → 合 Release → **重新发灰度**  
- 审核模板：PR + 发布记录 + 审核人 approve  

### 静态资源

- 参与旧 H5 **静态资源迁移**  
- 解决 Gulp/依赖兼容等发布阻塞  

### 可复用经验

- 灰度是**默认路径**，不是可选项  
- 监控外灰错误率、核心转化埋点  
- 回滚：切回主干桶或降外灰比例到 0

## 常见追问

**Q：内灰和外灰区别？**  
A：内灰**主动带参**，给测试/验证；外灰**用户无感按比例**，真实流量验证。

**Q：灰度出问题怎么办？**  
A：立即降比例或关闭外灰；静态资源版本回滚；复盘是否测试环境缺场景。

**Q：你在组内分享过灰度吗？**  
A：有 — 「如何配置与发布灰度」（转正材料 2.3）。
