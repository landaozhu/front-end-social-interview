# 你怎么做技术方案设计？

## 30 秒版

按团队规范：**5–10 PD 写技术设计文档**，>=10 PD **文档+评审会**。结构：背景目标 → 方案对比 → 接口/状态/风险 → 自测与回滚。举例：选座性能（profiling 后并行+分包）、灰度（网关迁移步骤）、日历高度（子组件回调）、条件退（状态矩阵+校验分层）。

## 2 分钟版

**模板要素**  
1. 背景与范围（哪些页面/端）  
2. 现状与指标 baseline  
3. 方案 A/B 对比（工期、风险、兼容性）  
4. 详细设计：组件、状态、接口、迁移策略  
5. 风险：高风险操作（公共 utils、package.json）  
6. 测试：自测 case、灰度计划、回滚  

**真实案例**  

| 项目 | 方案亮点 |
|------|----------|
| 灰度 | Node 升级 → 网关 → 内灰 → 外灰，前后端同桶 |
| webpack | 2→3→4 分步，lighthouse 不退化 |
| 日历高度 | 子测父设、高度数组缓存、+1/+4 像素修正 |
| 条件退 | 绝对/相对时间校验函数 + 审核态开关规则 |
| userMenu | html 预请求 + 事件 + 兜底三层 |

**评审后**  
- 文档底 comment「技术设计合理，审核通过」  
- 开发中偏差更新 PR 说明，不 silent 改 scope  

**20k 标准**  
- 方案可执行、可 Review、可复盘 — 不是空架构图
