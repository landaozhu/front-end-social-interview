# Vue 和 React 怎么选型？

## 考察点

- 二面听的是 **决策**，不是背区别表（区别见一面 `vue和react区别`）
- 必须挂自己的项目：猫眼 Vue、携程 React
- 承认 **入职时栈往往已定**，选型能力体现在「新项目看什么、迁移代价是什么」

---

## 30 秒版

两边都交过作业。猫眼选座 / 上单是 **Vue**（C 端多端 + B 端表单），Trip.com 地图是 **React SSR**。不是谁更高级。新项目我看四件事：**团队会什么、存量生态、页面形态、要不要 Concurrent / SSR 那套**。表单中后台、Vue 人多 → Vue；强交互、已有 React/Next、要精细打断更新 → React。核心交易页不会为了「试试新框架」推翻存量。

---

## 2 分钟版

### 入职现实

猫眼、携程的栈都不是我从零拍板。二面别装「我选了 React」。能讲的是：**在已定栈里把业务做成，并且知道换栈要付什么钱。**

### 新项目我会看什么

| 维度 | 偏 Vue | 偏 React |
|------|--------|----------|
| 团队 | Vue 人多、要上得快 | React / 海外协作 / 已有 Next |
| 页面 | 中后台表单、配置、审核流 | 复杂交互、地图、高度定制渲染 |
| 更新 | 改字段就更新，心智简单 | 要 `startTransition`、打断低优渲染 |
| 生态 | Element / Ant Design Vue | antd、ahooks、React 地图生态 |
| SSR | Nuxt 能做 | 携程这类国际站 React SSR 更常见 |

猫眼选座：状态机 + 多端 + 要写得快，Vue3 + 小程序分端合适。  
Trip.com 地图：SSR + Redux + Google Map，跟国际站 React 栈走。  
上单 2.0：存量 Vue2，渐进迁 Vue3 + qiankun，**不会为了 React 重写**。

### 不要用的理由

- 「React 更高级 / Vue 只适合小项目」——假的，猫眼 C 端一样重
- 「TS 只能 React」——Vue3 够用
- 「以后好招人」要看当地市场，上海两边都能招

### 和「最大挑战」那题的边界

选型讲 **为什么用这个**；挑战讲 **用了之后最难的坑**。别两题背成同一段。

## 常见追问

**Q：让你给新 C 端选，你选哪个？**  
A：先问团队和要不要 SSR / 小程序。纯 H5 复杂交互、人会 React → React；要小程序 + 中后台同一套人 → Vue 更省。给出前提，不要秒答一个名字。

**Q：Vue3 和 Hooks 很像，是不是没差了？**  
A：逻辑复用像（composable / hooks）。更新模型仍差：Vue 依赖收集，React 默认子树跟着 render。选型看的是模型和生态，不是「都能抽函数」。

**Q：能不能一边 Vue 一边 React？**  
A：微前端可以（上单就是 Vue2/3 共存）。新业务再加第三套，招人、基建、规范成本会爆。有明确边界（例如地图已是 React 国际站）才值得。

**Q：你更熟哪个？**  
A：近三年 Vue 更深（选座、上单）；React 在携程 SSR 核心页打过底，能独立做，不是只会 demo。
